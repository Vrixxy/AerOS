# Changelog

All notable changes to AerOS. Versions are not tagged yet; everything below is under Unreleased and grouped by area, newest first within each group.

## Unreleased

### Kernel
- Per-process ASLR: each process gets a random PML4 slot, inherited on `fork` and kept across `exec`.
- Kernel heap grown from about 2 MiB to 16 MiB using a multi-level page-table mapping.
- Copy-on-write `fork`, demand paging, process groups and sessions, most POSIX signals.
- Shell job control: `cmd &`, `jobs`, `wait`.

### Shell
- New commands: `grep` (`-i`, `-n`, `-c`), `find` (`-name`), `du`, `sort` (`-r`), `uniq` (`-c`), `tee`, `basename`, `dirname`, `seq`, `true`, `false`.
- Pipelines: `a | b | c` (up to four stages). `cat`, `head`, `tail`, `wc`, `grep`, `sort` and `uniq` read the previous stage's output when no file is named; the pipeline's status is the last stage's. Stages run one after another in the kernel, passing one buffer along.

### Threads
- Real threads: `clone` with `CLONE_VM|FS|FILES|SIGHAND|THREAD` (what `pthread_create` passes, with `CLONE_SETTLS`, `CLONE_PARENT_SETTID`, `CLONE_CHILD_SETTID` and `CLONE_CHILD_CLEARTID`) and `clone3` start a new task in the running process. The threads of a process share the address space, descriptor table, directory, signal handlers, limits and seccomp state; each has its own kernel stack, registers, FPU state, thread pointer (FS base, now saved and restored on every switch; a forked child keeps its parent's), signal mask, pending signals and alternate stack. Process state moves on a switch as one unit between processes and only the per-thread part inside one process, the leader's slot holds the shared copy while the process is switched out, and a leader that exits first lingers until its last thread is gone. `gettid` is the task id and `getpid` the process id, `tkill`/`tgkill` address one thread, `exit` ends the calling thread and `exit_group` the process, a fatal signal in one thread ends all, `execve` ends the other threads, and `wait4` reports the process when its last thread is done. `fork` from a thread copies the whole address space; `vfork` and `posix_spawn`'s `CLONE_VM|CLONE_VFORK` get a copy-on-write copy, not a shared one. The address space still has 128 pages for `mmap` (so thread stacks must be small; the standard library's 2 MiB default does not fit), and a process, threads included, holds at most 32 tasks system-wide.
- Futexes (`syscall/futex.rs`) are real wait queues keyed by process and address, with time-outs (relative, absolute, `CLOCK_REALTIME`) and signals ending a wait (EINTR): `WAIT`, `WAKE`, `WAIT_BITSET`, `WAKE_BITSET`, `REQUEUE`, `CMP_REQUEUE`, `WAKE_OP`, and the priority-inheritance calls `LOCK_PI`, `UNLOCK_PI` and `TRYLOCK_PI` (the lock is handed to the oldest waiter on unlock, an owner is boosted to the nice value of the most important waiter until it unlocks, a dead owner's lock is taken over with `OWNER_DIED`). A thread's `set_tid_address` word is cleared and woken as it exits, which is what `pthread_join` waits on, and its robust list is walked: every futex it still held gets `OWNER_DIED` and one waiter is woken. `set_robust_list` and `get_robust_list` work per thread.
- `userspace/threads` (`aeros-threads`) is a Rust `std` program built for musl that the boot-test runs as a real process (`AEROS_THREADS`, exit status 76): joins returning values, four threads doing 80,000 atomic increments, a mutex-protected list, a condition-variable ping-pong of 400 hand-offs, thread-locals, sleeps finishing in time order, channels, a barrier, scoped threads, twenty create-and-join cycles in a row, a file written by one thread and read by another, the process and thread ids, and raw `futex` checks of requeue, wake-op, priority-inheritance hand-over (including the lock bits and the `EDEADLK` an owner gets from a try-lock) and the robust list of a thread that exits holding a lock. Each step prints `AEROS_THREADS_STEP name ok`.

### Debugging
- `ptrace` (`syscall/ptrace.rs`): `TRACEME`, `ATTACH` (the parent, or a task holding the new `CAP_SYS_PTRACE`), `DETACH`, `CONT`, `SYSCALL`, `SINGLESTEP`, `KILL`, `PEEKTEXT`/`PEEKDATA`/`PEEKUSER`, `POKETEXT`/`POKEDATA`/`POKEUSER`, `GETREGS`/`SETREGS` (`user_regs_struct` order), `GETFPREGS`/`SETFPREGS` (the 512-byte FXSAVE image), `GETSIGINFO`, `GETEVENTMSG` and `SETOPTIONS` (`TRACESYSGOOD`, `TRACEEXEC`, `EXITKILL`). A traced task stops in its own context for a signal about to be delivered (the tracer can suppress or replace it), system call entry and exit (a negative `orig_rax` left at entry skips the call), a successful `execve`, `int3`, single-step traps and user faults (SIGSEGV/SIGFPE/SIGILL/SIGBUS); `wait4` reports the stops as `(signal << 8) | 0x7f`. Pokes into shared or copy-on-write pages (program text after a `fork`) give the tracee a private copy first. Signals sent to a traced task are always queued so the tracer sees them. Not done: threads as tracees, `SEIZE`/`INTERRUPT`, `TRACEFORK`/`TRACECLONE`/`TRACEEXIT`, debug registers, `PTRACE_GETREGSET`; a signal-delivery stop inside a system call comes after the syscall-exit stop, and a SIGSTOP given by the tracer is dropped instead of stopping the task.
- `wait4(-1)` now looks at every child (it used to follow only the first one) and at tasks the caller traces. A freed task slot no longer hands its old exit status to the next task that takes it (a second child in the same slot used to be reported as already finished).
- `userspace/ptrace` (`aeros-ptrace`) is the boot-test's tracer (`AEROS_PTRACE`, exit status 77): signal stop and suppression, entry/exit stops with a changed return value, skipped calls, `int3` stops, register and memory edits (data and code, with the parent proven untouched), single steps, FPU edits through `SETFPREGS`, the `execve` event, a traced null write, `PTRACE_KILL`, and `ATTACH`/`DETACH` on a running task. Each step prints `AEROS_PTRACE_STEP name ok`.

### Benchmarks
- `userspace/bench` runs the same static micro-benchmarks on AerOS (boot-test gate `AEROS_BENCH`) and on Linux (`tools/bench-linux.ps1`, a Debian-kernel initramfs in the same QEMU configuration). `docs/BENCHMARKS.md` has the first comparison: CPU and memory work is within 2-3x of Linux, but every system call is about 250x slower (37 µs for `getpid`), which makes file and pipe operations the same factor slower. Unprofiled; that is the next performance task.

### AerFS
- `aerfs.rs` is a copy-on-write filesystem: nothing is overwritten in place, every block pointer carries the CRC-32 of its target, and every change is one transaction committed by a single atomic superblock-sector write (two alternating slots), so a power cut leaves either the old tree or the new one and there is nothing to replay or repair. Files, directories and the inode table are 512-way radix trees; free space is rebuilt at mount from the metadata. `volume.rs` gives the VFS one interface over FAT and AerFS (an AerFS file is presented as a `fatfs::Node`), `datafs` mounts AerFS volumes under `/media` (USB sticks and SD cards that carry one mount by themselves), the shell gains `aerfs format|mount <disk>`, `fsck` works on them, and `/proc/mounts` shows the type. Limits: 256 MiB per volume, 58-byte names, no links, two volumes at once. `docs/AERFS.md` has the design and its limits.
- Tested by `tools/aerfs-host` (the same source against a RAM device that loses power mid-block: a 17-step script is cut at every sector write and the recovered filesystem must mount, pass `fsck` and equal the state before or after the step; 4,000 random operations against a model, a bit flipped in every block of a volume, running out of space, allocation-map agreement after remount) and by the boot-test gates `AEROS_AERFS_CRASH` and `AEROS_AERFS_VFS` (the cut-at-every-sector test inside the kernel through the volume layer, and the whole path through `/media` with a remount). It found one real flaw on the way: directories did not give back their space after entries were removed.
- Not done: AerFS as the home volume, an overlay that makes `/` itself writable, hard and symbolic links, encryption.

### Performance
- Profiling the benchmark (`kernel/src/perf.rs`, `AEROS_PERF` lines) found the reason system calls were 250 times slower than Linux and fixed three unrelated causes: the monotonic clock read the HPET over memory-mapped I/O on every call (it is now the calibrated time stamp counter, checked against the HPET and refined every ten seconds; `time.rs`, gate `AEROS_CLOCK`); the antivirus scan on every file open and close compared every signature needle at every byte (needles are now indexed by first byte, 1.7 ms to 40 µs for 4 KiB; `antivirus.rs`); and the idle boot task was handed the CPU whenever a process blocked and slept a whole timer tick (a blocked read, wait or exit now yields work-first; `scheduler.rs`). `getpid` 37,066 ns to 344 ns, pipe round trip 1.43 ms to 6 us, `fork` plus `wait4` 1.44 ms to 32 us, tmpfs create-write-read-unlink 6.4 ms to 0.25 ms. `docs/BENCHMARKS.md` has the table and the reasoning.

### Kernel image randomisation
- At the very start of boot (`uefi::relocate`, called first thing in `kernel_entry`, before the image data has been used) the kernel finds its own PE headers, picks a random 2 MiB-aligned free region from the firmware memory map with `aslr::pick_slot`, allocates it as loader code at that exact address, copies the headers and each section's data, applies its own base relocations for the new address (`aslr::apply_relocations`, 4,944 of them) and jumps to its entry point in the copy. The copy hands the original's pages back to the firmware. `AEROS_KASLR` reports where it moved from and to, how many slots there were, and checks that a pointer stored in the image points into the copy.
- Tested by `tools/aslr-host` (PE parsing, relocation of a synthetic image, malformed tables refused, uniform slot choice, and the real `BOOTX64.EFI` laid out as firmware does and moved twice with every relocated pointer checked to lie inside the image), by the whole boot-test running from a relocated image, and by `tools\kaslr-check.ps1`, which boots it several times and checks the base address varies.
- What it hides is the image: physical memory is still mapped at its own addresses on the kernel's identity map, so this is not a full KASLR (no higher-half kernel, no randomised direct map). It needs about 71 MiB of free memory at boot on top of the image the firmware already loaded; with less it stays where it was loaded (reported as `relocated=false`).

### Intel VT-x
- `vmx.rs` is a VT-x backend that runs the same smoke guests as the AMD-V path (a real-mode and a 64-bit program, plus the Linux boot-protocol probe) on VMX with EPT: `IA32_FEATURE_CONTROL`, CR0/CR4 fixed bits, `VMXON`, a VMCS per guest, an assembly VM-entry/exit path, and handling for CPUID, HLT, I/O, MSR, external-interrupt and EPT-violation exits. `svm.rs` now exports the guest programs and the Linux image loader so both backends use the same ones.
- **Not run on an Intel processor.** This machine is AMD and QEMU cannot offer VMX to a guest here. The pure parts (`vmx_logic.rs`: VMCS field encodings, control adjustment, access-rights conversion, the EPT tables, exit decoding) are tested on the host by `tools/vmx-host`, including a check that every field encoding matches the SDM layout and a software EPT walk of every mapped page; the rest is covered only by the compiler. The boot-test gate `AEROS_VMX` reports a skip here and requires all three guests to pass where VMX exists. The self-test is compiled into boot-test builds only, so an ordinary boot is unaffected. `docs/VTX.md` says how to run it and how to read a failure.
- Not done: the Linux desktop window and the guest devices are still AMD-V only (the ~3,200 lines in `svm.rs` that read VMCB fields need a backend interface), VPID, MSR and I/O bitmaps, NMI exiting.

### TLS 1.3
- `kernel/src/tls/` is a TLS 1.3 client written from scratch in `core`-only Rust (no heap): X25519 key exchange on the Ed25519 field arithmetic, ChaCha20-Poly1305 and AES-128-GCM records, the RFC 8446 key schedule (HMAC and HKDF over SHA-256), key updates, and `close_notify`. Server certificates are checked for real: an X.509 parser, RSA (PKCS#1 v1.5 and PSS, 2048 to 4096 bits) and ECDSA (P-256, P-384) and Ed25519 signatures, hostname matching (SANs, wildcards, IPv4 literals), validity dates against the RTC, CA and path-length constraints, key usage, and a built-in table of 136 trust anchors taken from the Mozilla list (`tools/make-tls-roots.py`). Only the SHA-256 suites are offered; HelloRetryRequest, client certificates, resumption and 0-RTT are not supported, and neither are name constraints (a certificate that has them is refused) or revocation checking (no CRL, OCSP or stapling).
- `tlsnet.rs` runs the client over the TCP engine (`https_get`, one session at a time in static memory) and the `https <host> [path]` shell command (COMMANDS=84) fetches a page and reports the certificate result.
- Testing is layered. `tools/tls-host` compiles the same source on the host and checks it against published vectors (RFC 7748, 8439, 5869, 8448, NIST GCM), against signatures and certificate chains made by OpenSSL (RSA, ECDSA, Ed25519, mixed chains, a non-CA intermediate, wrong names, expired and untrusted roots), against live `openssl s_server` handshakes with both suites, and against corrupted and truncated server bytes (every flipped or cut position in the handshake must fail). Key updates, replay and tampering are unit tests on two sessions. The boot-test adds `AEROS_TLS_KAT` (the vectors and four OpenSSL signatures inside the kernel) and `AEROS_TLS_NET` (the guest handshakes with two `openssl s_server` processes the harness starts on a throwaway CA, one RSA with ChaCha20-Poly1305 and one ECDSA with AES-128-GCM, and must refuse a wrong name and an unknown root). The test CA is made per run by `tools/make-tls-test-pki.py`; no private keys are committed. The boot-test also prints `AEROS_TLS_INTERNET` lines (informational, it needs the internet): the guest fetches `/` over TLS 1.3 from example.com, www.google.com, github.com, www.wikipedia.org, aws.amazon.com and www.microsoft.com with the built-in roots; all six verified and answered 200 on 2026-10-07.
- Not done: the AES S-box is a table lookup (not constant-time against cache attacks; ChaCha20-Poly1305 is preferred and listed first), TLS 1.2, session resumption, ALPN, and using TLS in the desktop browser and the package manager.

### Signed updates and measured boot
- `update <image> <signature>` (`update.rs`, administrator-only) installs a new boot image only if its Ed25519 signature verifies against a key trusted with `pkg trust`. The image is mounted-volume work done by the crash-tested FAT driver on the boot volume: written to `EFI/BOOT/BOOTX64.NEW`, read back and hashed, the running image copied to `BOOTX64.OLD`, then one crash-safe rename puts the new one in place. `update rollback` puts the old one back. Both are audit-logged and seal the new digest for the measured-boot check. A power cut at any sector write leaves either the old or the new image whole: the boot-test cuts power after every write count of a whole update on a RAM-disk FAT volume (`AEROS_UPDATE`, 55 cases, none torn) and also checks a wrong-key signature, a tampered image and an empty key store are refused without touching the volume.
- Measured boot (`measure.rs`): at start-up the boot image on the FAT volume and the built-in program archive are hashed and folded into a running SHA-256 register the way a TPM extends a PCR; `measure` prints the log, the register and whether the image matches the digest sealed by `update` or `measure seal` (`/data/MEASURE.REF`); a mismatch is written to the audit log as an alert. Gates `AEROS_MEASURE` and `AEROS_MEASURE_TEST`.
- Not done: UEFI Secure Boot signing (the firmware's keys are outside the project), a TPM driver (the register is in software, so it does not protect against someone who can alter the kernel and the sealed file together), updating anything but the boot image, refusing to boot a changed image.

### Swap and stack protection
- Swap (`swap.rs`, with `process_swap_out/in` in `arch/paging.rs`): a partition formatted as swap (GPT type "Linux swap" or MBR type 0x82, and the `SWAPSPACE2` signature in its first page) on the boot disk becomes a pool of up to 16,384 4 KiB slots, read and written straight through the disk driver. Heap, anonymous-mapping and grown-stack pages of processes that are not running are evicted when memory is critical (`oom::relieve` tries it before killing anything); pages still shared with a forked relative stay in memory. An evicted page's page-table entry is "not present, swapped" with its slot, and touching it (a user fault, a kernel copy to or from user memory, `ptrace`) reads it back. `fork`, `mprotect` and file-backed `mmap` bring a process's pages back first; `munmap`, `exec` and exit free the slots. `/proc/meminfo` shows SwapTotal and SwapFree and the `swap` shell command shows use (COMMANDS=81).
- Boot-test (`AEROS_SWAP`): a 6 MiB swap area on the virtio test disk, a std program that keeps heap and mmap regions filled with a versioned pattern, rewrites and checks pages for 0.6 s while the kernel evicts eight pages on every tick: ~700 pages written, ~600 read back, no mismatch, all slots free after the program exits.
- Stack protector: the kernel is built with `-Zstack-protector=strong` (`.cargo/config.toml`; the flag is unstable, so `RUSTC_BOOTSTRAP=1` is set there too). `stackguard.rs` supplies the MSVC-style `__security_cookie` (redrawn from RDRAND and the TSC first thing in `kernel_entry`, low byte clear) and `__security_check_cookie`, which prints `AEROS_STACK_SMASH` and halts. Boot-test (`AEROS_STACK_PROTECTOR`): the cookie differs from its default, a function with a buffer loads it, the image holds hundreds of check calls, the check accepts the right value and rejects a wrong one.
- Not done: encrypted swap.

### DMA protection
- AMD-Vi IOMMU driver (`iommu.rs`): the IVRS table gives the unit's registers, the address ranges firmware wants mapped one-to-one and the interrupt-forwarding flags of special devices. Every PCI function found at boot (plus the alias and special devices IVRS names) gets a device table entry in one shared domain with a 4-level page table; every other device id is pointed at an empty table and is blocked. The domain maps only memory drivers set aside for DMA (`FrameAllocator::allocate_dma`, used by the AHCI, NVMe, xHCI, virtio, e1000, RTL8139/8168, HDA and AC'97 drivers) and, for the length of one command, the buffer a caller hands to AHCI (`iommu::window`, reference-counted per page). Interrupts pass through unmapped. Commands (`INVALIDATE_DEVTAB_ENTRY`, `INVALIDATE_IOMMU_PAGES`, `COMPLETION_WAIT`) and the event log are real; a fault shows up in `/proc/iommu` (state, mapped pages, fault count, last fault).
- The tables are built before the drivers start; `enable` runs once they are up and keeps the unit on only if the boot disk reads back the same first sector through it, so a mistake costs the protection and not the boot.
- Boot-test (`AEROS_IOMMU`): QEMU's `amd-iommu,dma-remap=on` plus the `edu` test device, whose DMA engine is pointed at a page: it reads and writes the page at a mapped address that is not the page's physical one, its writes and reads at the page's unmapped physical address are blocked and logged, and a withdrawn mapping closes the page again (which also proves the invalidation). Every driver's DMA in the rest of the boot-test runs through the unit.
- Not done: Intel VT-d, interrupt remapping, a domain per device, ATS/PRI, large pages in the I/O page table. Only QEMU has run this; on real hardware the unity ranges, device-entry flags and alias entries are parsed from the IVRS but untested.

### ACPI
- AML interpreter (`aml.rs`, no kernel dependencies, fixed-size tables, no allocation): definition blocks (DSDT and every SSDT) are executed into a namespace of up to 12,288 objects (scopes, devices, processors, thermal zones, power resources, names, methods, operation regions, fields, index and bank fields, buffer fields, mutexes, events, aliases). Methods are interpreted from the bytecode: control flow, integer/string/buffer/package operations, references (`Index`, `DerefOf`, `RefOf`, `CondRefOf`), conversions, `Match`, `Concatenate`, `Mid`, `Stall`/`Sleep`, `Notify` (counted), predefined `\_OSI`, `\_OS_`, `\_REV`, `\_GL_`. Integers are 32-bit for a revision-1 DSDT and 64-bit otherwise. Package elements that name objects defined later are resolved when used. Operation regions: SystemMemory (only mapped addresses), SystemIO, PCI_Config (functions directly under a root bridge); EmbeddedControl and the rest report `Unsupported`.
- `acpi_ns.rs` loads the tables at boot, calls `_PIC(1)`, and serves `\_S5_` to the power-off path (the old byte scan stays as a cross-check), resource-template decoding and the new `acpi` shell command (`acpi`, `acpi tree`, `acpi eval <path> [args]`, `acpi crs <path>`). `pci::config_read/config_write` and `paging::kernel_range_mapped` back the hardware accesses.
- Tests: `tools/aml-host` runs the interpreter on a host against a DSDT captured from QEMU (`cargo test` in that directory: namespace, `_S5_`, PCI root `_HID`/`_CRS`, `_PRT` in PIC and APIC mode, every `_STA`/`_CRS`/`_HID`/`_ADR`); the boot-test gates `AEROS_AML` and `AEROS_AML_QUERIES` (S5 equals the byte scan, PCI0 `_CRS` holds port 0xCF8, COM1 `_CRS` is I/O 0x3F8 plus IRQ 4, all 128 `_PRT` sources are devices, LNKA `_CRS` read through PCI config space).
- Not done: GPE/SCI handling (so no hot-plug or button events), `_INI`/`_REG` calls, sleep states beyond S5, battery, thermal and CPU frequency control, EC regions, `Load`/`LoadTable`, nested PCI buses in `PCI_Config` regions.

- Priorities: each task has a nice value (-20..19, inherited on `fork`); the scheduler prefers lower values but ages passed-over tasks so none starves. Set with `renice` (privileged) or `setpriority`, read with `getpriority`; `ps` shows an NI column. Equal nice values behave like the previous round-robin.

- SMP job scheduler (`smpsched.rs`): every application processor has its own run queue; a job carries a nice value and an affinity mask, goes to the least loaded CPU its mask allows, runs in priority order with aging, and an idle processor takes the best job it is allowed to run from the busiest queue. `bench smp` hashes on every processor at once, `/proc/schedstat` shows jobs per CPU and steals. User tasks still run only on the bootstrap processor (the Linux process state is global), so this is not a preemptive multi-CPU task scheduler. `AEROS_SMP_SCHED` checks placement, stealing, priority order, affinity, refusal of an impossible mask and, with `-CpuCount 4`, balancing and stealing across three processors.

### Package manager
- `pkg` (privileged): `install <file> [signature]`, `list`, `remove`, `rollback`, `verify`, `path <name>` and `trust <key-hex>`. A package is a text header (name, version, up to 16 files with path, mode, size and SHA-256) followed by the files' bytes; the 64-byte Ed25519 signature next to it covers the whole file and has to verify against a key added with `pkg trust`. Nothing is read from a package before its signature checks out, every file is hashed as it is written and compared with the header, paths may not be absolute or contain `.` or `..`, and a failed install removes whatever it wrote. Files go to `/home/pkg/apps/<name>/<version>/`; the previous version stays installed so `rollback` only changes a pointer, and a third version removes the oldest. `verify` re-hashes the installed files against the recorded manifest. The boot-test (`AEROS_PKG`) runs install, update, rollback, forward again, rotation, an untrusted key, a one-byte change, a short signature, a wrong declared hash, a path escape, a truncated body and tampering with an installed file, using packages signed offline (`tools/make-pkg-vectors.py`). Removing the signature check and the hash check together makes it fail. `tools/aeros-pkg.py` builds and signs packages on the host (`keygen`, `pubkey`, `build`, `sign`; needs Python and OpenSSL). There are no dependencies between packages.

### Security
- Ed25519 signature verification and SHA-512 (`ed25519.rs`), checked against signatures generated with OpenSSL, including tampered, non-canonical and wrong-key cases. `sigcheck <file> <signature-file> <public-key-hex>` verifies a signed file. No update key is built in yet and no secure-boot chain uses this; it is the primitive for signed updates.

- Capabilities: each process has effective and permitted capability sets, full by default, inherited on `fork`, kept across `exec` and only ever shrinkable (`capset` can drop but never regain). `capget`/`capset` report and change the real sets. Enforced for raising a process's priority (`CAP_SYS_NICE`), signalling another process (`CAP_KILL`), `chown`/`fchown`/`fchownat` (`CAP_CHOWN`), binding a port below 1024 (`CAP_NET_BIND_SERVICE`, EACCES), setting the clock with `clock_settime` and `settimeofday` (`CAP_SYS_TIME`), `reboot` (`CAP_SYS_BOOT`) and `mount`/`umount2` (`CAP_SYS_ADMIN`); a user process that drops them gets EPERM (EACCES for the port). `AEROS_CAPABILITY` drops each in turn and checks the refusal and that the call works again afterwards. Everything else root can do is not gated. `clock_gettime` now also answers `CLOCK_REALTIME` and the coarse, raw and CPU-time clocks (the last two report elapsed time), and `reboot` validates the Linux magic numbers.
- Seccomp filter mode: `seccomp(SECCOMP_SET_MODE_FILTER)` takes a classic-BPF program that is validated, then run on every syscall (allow, fail with an errno, or kill). One filter per process, inherited across `fork` and `exec`; stacking filters is not supported.

### Benchmarks
- `bench` shell command: memcpy, SHA-256 and random-fill throughput plus file lookup, tmpfs write and `yield` rates, each measured over a fixed time slice.

### Memory
- Slab allocator (`slab.rs`): seven size classes from 16 to 1024 bytes carved from 4 KiB heap pages, each page with a header, free list and use count; an empty page goes back to the heap (one spare per class is kept, `reclaim` returns the spares under pressure), freed objects are zeroed, and a double free, a wrong-size free or a pointer that is not a live object is refused. Layouts above 1 KiB or 64-byte alignment fall through to the heap. The scheduler's per-task FPU areas (832 bytes, 64-byte aligned) come from it; `/proc/slabinfo` shows the classes. `AEROS_SLAB` allocates 400 mixed objects, checks alignment and contents, frees in a shuffled order and requires the heap's free bytes and allocation count to come back exactly.
- Memory-pressure levels (low at 10% free, critical at 3%) shown by `free`. When `fork` or `mmap` fails under critical pressure, the other user task holding the most pages is terminated (`AEROS_OOM_KILL`). `ps` now shows a PAGES column with each process's resident pages.

### Storage
- Block layer (`block.rs`) between the filesystems and every disk driver: one `Disk` type for AHCI, NVMe, USB, SD and virtio-blk, per-disk counters (`/proc/diskstats`), a write-through page cache of up to 256 4 KiB pages that fills on read, reads ahead of a sequential reader, and gives its pages back under memory pressure (`oom::relieve` empties it before it kills a process; `/proc/vmstat` and the Cached line of `/proc/meminfo` show it). A failed write drops the cached copy. `block::submit` is an I/O scheduler for batches: requests are issued in one upward sweep from the head position (C-LOOK), neighbouring requests of one kind are merged into runs of up to eight sectors, a barrier ends a group, and a group in which a write overlaps another request keeps its submission order. FAT file reads gather the clusters they need and submit them as one batch. The boot-test (`AEROS_BLOCK`) shows 48,233 sectors of head travel for a random batch in submission order against 7,106 scheduled, 48 commands against 7 for a contiguous one, barrier and overlap ordering, cache hits, write-through, a power-cut write, LRU eviction, read-ahead and a full reclaim that returns every page; reverting the sort makes it fail.
- Mount table (`mounts.rs`): `/`, `/tmp`, `/proc`, `/sys`, `/home`, `/media/<label>` and bind mounts are listed by `mount` and `/proc/mounts`. `mount --bind <directory on /home or /media> <directory in the root tree>` (privileged) and `umount <target>` change the table, as do the Linux `mount(MS_BIND)` and `umount2` calls (they need the new `CAP_SYS_ADMIN`); a bound directory cannot be removed or renamed, and paths are rewritten to the volume before any VFS call, so every file operation works on it. At boot `/var`, `/opt`, `/srv` and `/root` are bound to `/home/.root/...`, which makes those directories of the root tree writable and persistent (`AEROS_MOUNTS` writes through `/var`, renames, lists, remounts the volume and reads the file back; removing the mount-point protection makes it fail). The rest of the root tree is still read-only and `/etc` is not persistent.

- Installer (`installer.rs`) on disks that already hold data: a disk whose only content is a valid GPT can take the system in its largest free gap of at least 288 MiB (`MIN_PARTITION_SECTORS`), and nothing is written until the new partition is formatted and filled; only then is the entry added, backup table first and primary last (a power cut at every one of the 66 writes leaves at least one complete valid table), and afterwards every earlier entry is compared byte for byte. A disk with a damaged table (bad header or array checksum, a different backup, overlapping or out-of-range entries), a table with no free slot or no big enough gap, an MBR-only disk, or raw data is refused with the reason (`refusal=` in `AEROS_INSTALL`). A blank disk still gets the whole disk, as before. Existing disks need permission: `install <disk> --yes` in the shell (privileged; `install` alone lists the disks and what would happen, the boot disk is never a target), or an `INSTALL.CFG` containing `free-space` on the boot disk for an unattended install. `AEROS_INSTALLER` checks the planning, the refusals and the power-cut property on a RAM disk (replacing the table checks or the write order makes it fail), and `tools/test-install-existing.ps1` does the whole thing in QEMU: a 640 MiB disk with a 96 MiB partition is left byte-identical when no permission is given, with permission the new partition goes after it (`tools/make-gpt-disk.py` checks both tables, the old partition's SHA-256 and the FAT32 volume) and the machine boots from the result.

### Services

### Services
- `svc` shell command (privileged): `add`, `start`, `stop`, `restart`, `rm` and `list` for named background programs.

- `fsck [--repair] [mount-point]` (privileged) checks a `/home` or `/media` filesystem using the raw FAT: broken chains, clusters shared by two entries, sizes larger than their chain, and clusters no entry owns. With `--repair` it cuts broken chains at their last good cluster, lowers oversize files to fit, and frees leaked clusters; shared clusters are only reported. The power-loss test runs a repair pass after every simulated cut and requires a clean second pass (426 leaked clusters repaired across 189 cases). The home volume is checked when it is mounted (`AEROS_HOME_FSCK`) and repaired automatically if it is damaged; leaked clusters alone are left for a manual `fsck --repair`, and volumes over about a million clusters are skipped.

- Hostile-disk hardening for the `/home` and `/media` filesystem: a directory whose cluster chain loops (or never ends) used to make listing run forever, and `extend_dir` had an unbounded loop on the same input. Directories are now capped at the format's 65,536 entries, `extend_dir` reports corruption after a bounded walk, and directory reads keep a chain cursor instead of re-walking the chain for every entry. A directed test builds exactly that looping directory; with the cap removed the boot hangs, with it the test passes. Boot fuzzing now also covers random seccomp BPF programs, the shell parser, pipeline splitter and path normalizer, VFS path lookups, Ed25519 on garbage input, 150 randomly corrupted FAT images for each FAT implementation, mutated package headers, random `/proc` paths (which must never map outside the hidden directory) and generated TCP frames with fixed-up checksums (184k inputs in about 5 seconds).

### Tracing
- The last 64 Linux syscalls (task, number, first argument, time) are kept in a ring and listed by the privileged `strace [lines]` command, with names for about 50 common syscalls.

### Crash reporting
- The last 8 user processes killed by a CPU fault are recorded (pid, vector, error code, fault address, instruction pointer, uptime) and listed by the privileged `crashes` command. `crashes save [path]` writes a report (the records plus the last 40 kernel-log lines, mode 0600) to `/home/crash-report.txt` or the given path, so it survives a reboot when saved under `/home`.

### Logging
- 16 KiB kernel log ring fed by all serial output, with a privileged `dmesg [lines]` command.

### Filesystem
- `/proc` (read-only): `version`, `uptime`, `meminfo`, `cpuinfo`, `loadavg`, `stat` (CPU time counters are zero; `btime`, process count and CPU lines are real), `mounts`, `filesystems`, `sys/kernel/{ostype,osrelease,hostname,pid_max}`, `sys/vm/{overcommit_memory,swappiness}`, and `self/` (or the process's own id) with `status` (pid, parent, resident memory, effective and permitted capabilities, seccomp mode), `stat`, `statm`, `comm`, `maps` (the process's regions in Linux's format: image pages grouped by permission, `[heap]`, anonymous mappings, `[stack]` including grown pages) and empty `cmdline` and `environ`. It is not a mount: the VFS rewrites `/proc/...` to a hidden directory under `/tmp` and regenerates the files it names just before opening, statting or listing them, so every tool that already reads files can read it, and two readers of one file at the same moment share a copy. Other processes' directories, `/proc/self/fd` and `/proc/self/exe` as a file (readlink still answers) are not provided; writes and creates under `/proc` get EACCES. A small `/sys` works the same way: `devices/system/cpu/{online,possible,present,kernel_max}` and `kernel/mm/transparent_hugepage/enabled`. The tmpfs grew to 96 nodes and 56 file slots to hold both.
- Symlinks on tmpfs (`ln -s`, `readlink`, leaf-only following with a hop limit).
- `~/.aershrc`-style startup script run at login (`/home/.aershrc`).

### Linux compatibility

Not exercised by the boot-test beyond the shared vector helper, since the syscalls take user pointers.
- New syscalls: `lstat`, `symlink`, `symlinkat`, `creat`, `getrlimit`, `getpgrp`, `getgroups`, `getresuid`, `getresgid`, `truncate`, `ppoll`, `getrusage`, `times`, `sched_getparam`, `sched_getscheduler`, `prctl` (name, dumpable, no-new-privs only).
- `readlink` and `readlinkat` now return real symlink targets.
- `epoll`, AF_UNIX sockets, seccomp strict mode.

- Runtime-probe syscalls: `capget`/`capset` (see Security), `getpriority`/`setpriority`, `sched_get_priority_max`/`min`, `sched_setaffinity` (validated, not enforced).
- More syscalls: `faccessat`, `epoll_create`, `epoll_pwait` (signal mask ignored), `utimensat` (checks the path, records no time), `fadvise64`, `mlock`/`munlock`/`mlockall`/`munlockall`, `setuid`/`setgid`/`setgroups` (only root values accepted), `chroot` (always refused).
- `eventfd` and `eventfd2` (counter, `EFD_SEMAPHORE`, `EFD_CLOEXEC`; `EFD_NONBLOCK` is accepted but reads and writes always retry briefly and then return EAGAIN, as pipes do). Works with `poll`, `select` and `epoll`; shares `pipe`'s slots (eight in all). Mutation check: ignoring semaphore mode fails the boot-test. `timerfd_create`, `timerfd_settime` (relative or `TFD_TIMER_ABSTIME`, one-shot or periodic, returns the previous setting) and `timerfd_gettime`: the descriptor reports readable once the timer has expired, a read returns the number of expiries since the last read and waits for the next one if the timer is armed (EAGAIN if it is not), and all three clock IDs use the monotonic clock. Dropping the periodic catch-up count fails the boot-test. `signalfd` is not implemented.
- More syscalls: `flock` (validated, locks are not enforced), `sync`, `syncfs`, `close_range` (including `CLOSE_RANGE_CLOEXEC`), `preadv`, `pwritev`, `fallocate` (mode 0 grows the file, `KEEP_SIZE` is accepted), `fchdir`, `personality` (only `PER_LINUX`), `sched_setscheduler` (default policies only; real-time policies get EPERM), `mincore` (reports every page resident) and `membarrier` (query only). `memfd_create` makes a hidden `/tmp/.memfd-N` file that is deleted when its last descriptor closes or its process exits (the name argument is only checked, and sealing is not supported). `sendfile` (file to a file, pipe or unix socket, with or without an offset) and `copy_file_range` (file to file, with or without offsets; no reflinks, flags must be 0) copy in 256-byte steps, up to 64 KiB per call. Not done: `splice`, `mremap`, `link`/`linkat`, `recvmsg`/`sendmsg`, `inotify`.
- `statfs` and `fstatfs` with real sizes for tmpfs, the FAT mounts and the initramfs (descriptors that are not files, such as pipes and sockets, report tmpfs with no free space).
- `select` and `pselect6` (readiness shared with `poll`; no exception conditions, signal mask ignored).
- Socket API: `setsockopt` (accepted, not acted on), `getsockopt` (`SO_TYPE`, `SO_ERROR`, `SO_ACCEPTCONN`), `getsockname`, `getpeername`, `shutdown`.

### Networking
- IPv6 (`ipv6.rs`, `ip.rs`): one 16-byte address type for both versions (IPv4 is the IPv4-mapped form). At boot the machine solicits a router advertisement, takes the first `/64` prefix with the autonomous flag (global address from the EUI-64 identifier), the router's link-layer address and any DNS server from it, resolves the router with a neighbor solicitation and announces its global address. While the stack runs (`tcpnet::poll`) it answers neighbor solicitations and echo requests for its own addresses (neighbor discovery messages need hop limit 255), learns neighbours into an eight-entry cache, and frames and parses TCP and UDP over IPv6 with their pseudo-header checksums; TCP over IPv6 uses a 1440-byte MSS. `socket(AF_INET6)` works for streams and datagrams with `sockaddr_in6` (28 bytes) in `bind`, `connect`, `accept`, `sendto`, `recvfrom`, `getsockname` and `getpeername`; an `AF_INET6` socket is dual-stack (an IPv4 peer shows as `::ffff:a.b.c.d`), an `AF_INET` listener refuses IPv6 peers, and the unspecified address as a destination means this machine, as on Linux. `::1` stays in the kernel. `IPV6_V6ONLY` is stored and turns the dual-stack off for a listener. Shell: `ping <ipv6>`, `dns -6 <name>` (an AAAA query through the DHCP-supplied DNS server), `ip`, `route` and `arp` show the IPv6 address, router, DNS server and neighbours, and `netstat` lists the real sockets and bound UDP ports. The boot-test checks neighbour solicitation and echo answers (and that a solicitation with hop limit 64 or for someone else's address is ignored), a corrupted echo and TCP segment, address text round trips, `AF_INET6` TCP and UDP over `::1` with the dual-stack and refusal cases, and then, through the card, an HTTP download from the host over IPv6 (`AEROS_HTTP6`, the host serves on `::1` and the guest reaches it as `fec0::2`) and an AAAA lookup for `localhost` (`AEROS_DNS6`). Not done: duplicate address detection, address lifetimes and re-advertisements, DNS transport over IPv6, extension headers and fragmentation, IPv6 in the browser.
- TCP selective acknowledgement: SACK-permitted is offered on every SYN and used when both ends send it. A receiver keeps segments that arrive beyond the next expected byte (up to four ranges, merged when they touch, most recent first) and reports them as SACK blocks on its duplicate acknowledgements; a sender keeps a scoreboard of what the peer has, and after three duplicate acknowledgements resends only the holes (two segments per acknowledgement), sending new data meanwhile by counting only the bytes not yet received. Without SACK it still goes back to the first unacknowledged byte. The receiver's buffering also helps peers that send no SACK. `AEROS_TCP_ENGINE` checks the block layout exactly (a single block, two adjacent segments merged, a second block listed first, the cumulative acknowledgement jumping over everything contiguous once the gap fills, the stream intact) and, for a burst of three lost segments, that the SACK sender finishes without a timeout and puts at least ten fewer data segments on the wire than a sender without SACK (the real-card runs of the same engine pass too).
- Socket options (`sockopt.rs`): `setsockopt` stores and `getsockopt` returns `SO_REUSEADDR`, `SO_REUSEPORT`, `SO_KEEPALIVE`, `SO_BROADCAST`, `SO_LINGER`, `SO_RCVTIMEO`, `SO_SNDTIMEO`, `SO_SNDBUF` and `SO_RCVBUF` (doubled and clamped like Linux), `SO_DOMAIN`, `SO_PROTOCOL`, `IP_TTL`, `IP_TOS`, `TCP_NODELAY`, `TCP_CORK`, `TCP_QUICKACK`, `TCP_KEEPIDLE`/`KEEPINTVL`/`KEEPCNT` and `IPV6_V6ONLY`, with Linux's errors (EINVAL for a short value, EDOM for a bad `timeval`, ENOPROTOOPT for an unknown option). Acted on: `SO_REUSEADDR` (a restarted server can bind while connections from its previous run linger in `TIME_WAIT`; only a listener blocks it), receive and send time-outs on blocking stream and datagram sockets (EAGAIN when they pass), `SO_LINGER` with a zero time (closing sends a reset), `IPV6_V6ONLY`. Stored and reported only: keep-alive probing, `TCP_NODELAY` (there is no Nagle delay to turn off), the TTL and TOS actually put on packets, buffer sizes (the windows stay 8 KiB). `recv` handles `MSG_PEEK`, `MSG_WAITALL`, `MSG_DONTWAIT` and, for datagrams, `MSG_TRUNC` (the real length is returned when the datagram was cut); `FIONREAD` and `FIONBIO` work on sockets. A bug found on the way: closing a listening socket also destroyed the connections it had already accepted; they now live on. `AEROS_SOCKOPT` covers all of it.
- The e1000 now accepts multicast frames. It had been dropping them, which is why no IPv6 router advertisement ever arrived and the old IPv6 check had to be lenient; the harness now requires the whole IPv6 exchange.
- UDP rebuilt around a port table (`udp.rs`): every bound port owns a queue of four datagrams, filled by one shared receive path, so a datagram that arrives while its owner is busy is kept instead of dropped. Sockets can now `bind` (port 0 or taken ports behave as on Linux: EADDRINUSE), receive from any peer unless connected, block in `recvfrom` (EAGAIN with `O_NONBLOCK`/`SOCK_NONBLOCK`/`MSG_DONTWAIT`, EINTR on a signal), and report readiness to `poll`/`select`/`epoll` (UDP sockets never showed as readable before). Datagrams to 127.x.x.x or the machine's own address stay inside the kernel. The kernel's own DNS and NTP clients bind a port implicitly when they send, so their replies are queued too. A datagram longer than the receive buffer is cut to fit. Boot-test: the port table and the socket layer over loopback (`AEROS_UDP`), plus the existing real DNS lookup and NTP exchange through the card.
- The browser's HTTP client (`net::http_get`) now runs on the TCP engine instead of its own single-shot handshake: connect with retransmission, windowed receive, orderly close, and a five-second idle timeout. The boot-test downloads a 6,000-byte body from a one-shot HTTP server on the host over the card (`AEROS_HTTP_CLIENT`) and the harness checks the request line it received. The old retransmit-backoff self-test went away with the code it covered; `tcp.rs` has the engine's own tests.
- TCP sockets for programs: `socket(AF_INET, SOCK_STREAM)` with `bind`, `listen`, `accept`/`accept4`, `connect`, `read`/`write`, `send`/`recv` (with `MSG_DONTWAIT`, `MSG_NOSIGNAL`), `shutdown`, `getsockname`/`getpeername`, `getsockopt` (`SO_ERROR`, `SO_TYPE`, `SO_ACCEPTCONN`, buffer sizes, `TCP_NODELAY`, `TCP_MAXSEG`), `poll`/`select`/`epoll`, `sendfile` to a socket and `O_NONBLOCK` (`SOCK_NONBLOCK`, `fcntl`). Eight connections at most, with an 8 KiB window each (a finished connection still waiting out `TIME_WAIT` gives up its slot when a new socket needs one). Blocking calls wait until the engine can answer and return EINTR on a signal; `connect` gives up after 30 seconds. There is no background network thread: the stack runs when a socket call, a `poll`, a sleep or any syscall happens while a socket exists, so a connection a program closed and left behind finishes its close only when something else makes a syscall. Connections to 127.x.x.x or the machine's own address stay inside the kernel. Not done: ancillary data (`SCM_RIGHTS`) and `sendmmsg`/`recvmmsg`, `SO_REUSEADDR` (accepted, no effect), out-of-band data, `SO_RCVTIMEO` and `SO_SNDTIMEO`. The boot-test covers it twice: a kernel-side loopback run (handshake, 24 KB up and 6 KB down, half-close, refused connection, `SO_ERROR` clearing), and a real run where the guest's echo server on the socket layer takes 30,000 bytes pushed from the host through the card and sends them back intact (`AEROS_TCP_NET`).
- `poll`, `ppoll` and `select` now keep rescanning while they wait instead of sleeping for the whole timeout once, so they return as soon as a descriptor is ready; a negative `poll` timeout (and `ppoll` without a timeout) waits until something is ready or a signal arrives.
- TCP engine (`tcp.rs`), a state machine independent of any card (`tcpnet.rs` connects it to the card and to an in-kernel loopback): three-way handshake both ways, `listen`/`accept` with a backlog of four, retransmission with a measured timeout and exponential backoff, slow start, congestion avoidance, fast retransmit (go back to the first unacknowledged byte, since out-of-order data is not kept), a receive window with zero-window probing, RST handling, and the full close sequence with `TIME_WAIT`. The MSS option is sent on every SYN and SYN-ACK and the peer's is honoured (536 when it sends none), so a path with a small MTU gets small segments; a simulated peer advertising 536 shows no larger segment going out. Not done: SACK, window scaling, delayed ACK, out-of-order buffering and urgent data. A boot-test (`AEROS_TCP_ENGINE`) runs it between two simulated hosts over a wire that drops segments: a clean 60 KB upload with a 20 KB download, a drop of every sixth segment, a single dropped segment that must be recovered by fast retransmit without a timeout, a receiver that reads 300 bytes per millisecond, a refused connection, a peer that never answers (exactly five SYN retries), 6,000 random hostile segments, duplicated segments and reversed delivery order. Disabling fast retransmit and slow-start growth makes the gate fail.
- Packet-filter firewall (`fw`, `fw deny <tcp|udp|any> <port>`, `fw clear`) applied at the single NIC receive path.
- The boot-test's one-connection echo server in `net.rs` still uses hand-rolled segments; everything else goes through the TCP engine.

### Storage
- FAT free-cluster search now reads each FAT sector once instead of once per cluster. This was the cause of boot-test runs intermittently taking several minutes or timing out; a full run now takes under two minutes.

- Power-loss testing of the FAT writer: a boot-test hook drops every sector write after a chosen count, and the test cuts replace, create and delete operations at every possible point over five file-size pairs, checking each result for chains that run into free clusters, shared clusters, short chains and torn or lost files. It runs on a RAM-backed FAT16 volume it formats itself, since QEMU's `vvfat` ESP aborts on such writes. FAT32 directories share the fix but are not covered by the test.
- Fixed two FAT write bugs the test exposed: replacing a file freed the old chain before the new data and directory entry were written (a power cut left a directory entry pointing at freed clusters), and a replace could leave a second entry with the same name. The new data is now written first, one directory-entry write publishes it, and only then is the old chain freed; deleting marks the entry first and frees the chain after.

- The `/home` and `/media` filesystem now shrinks a file in a power-safe order too (new size, then cut the chain, then free the tail). A power-loss test covers it: create, append, shrink, truncate-to-empty and delete are each cut at every possible sector write on a RAM disk, then the volume structure and the file's bytes are checked. A mutation check (putting the old truncate order back) makes the test report 48 structural failures and 48 torn files, so it can fail. Renaming a file over an existing one is power-safe: the destination's entry is re-pointed at the source's data in one sector write, then the source name is removed, then the old data is freed, so a cut never loses the file (it can briefly leave both names sharing it, which `fsck --repair` reports as `duplicates` and resolves). The test covers this with a rename scenario; putting the old delete-first behaviour back makes it report 13 torn files.

### Testing
- The boot-test now runs 2,500 random command lines through the real shell (`AEROS_SHELL_FUZZ`, last step before ready): read-only commands and the privileged log readers with paths, flags, numbers and junk as arguments, some piped or redirected, and the file-changing commands on paths under `/tmp` only. Commands that reboot, kill, spawn, change accounts or firewall rules, touch disks or take long are skipped; the shell runs as root because every `ear` costs a deliberate two-second re-authentication. No panic or hang turned up. The harness's readiness limit went from 240 to 420 seconds because the suite had grown to within a minute of it.
- `.github/workflows/ci.yml` checks formatting, runs clippy with `-D warnings` for the default, `boot-test` and `linux-headless` feature sets, and builds the release and boot-test kernels on every push to `main` and every pull request; a manual run can also execute `tools	est.ps1` on a Windows runner with QEMU from Chocolatey. The workflow has not been run on GitHub yet, and the boot-test harness assumes QEMU is accelerated (its 240-second readiness limit may be too short under plain emulation).
- Syscall fuzzing in two forms, both in every boot-test. A kernel-side run calls the Linux dispatcher 27,000 times with random numbers and arguments where no user memory is mapped, which exercises argument checks and descriptor lookups. A hand-assembled user process (`tools/make-fuzz-probe.py` generates it; `FUZZ_SEED` and `FUZZ_ROUNDS` change its seed and length) then makes 40,000 random syscalls from a table of the ones that are implemented, with arguments drawn from small numbers, -1, 0, random words and pointers into its own buffer, which starts with path strings for `/tmp`, `/proc` and `/sys`; it skips calls that end, signal or block the process, change its memory map and limits, or write to the console. A clean run exits 0 (`AEROS_SYSCALL_FUZZ`); a panic in the kernel halts the boot. Planting a panic behind a valid user pointer in `memfd_create` makes the boot fail, so the process does reach such code.
- `tools\test.ps1` takes `-MemoryMiB` (default 512) and accepts `-CpuCount 1`. Measured limits are in `docs/REQUIREMENTS.md`: the kernel loads from 192 MiB, the full boot-test needs about 384 MiB, and one CPU boots to the desktop.
- Capability enforcement is tested by dropping `CAP_CHOWN` and `CAP_SYS_NICE` and requiring EPERM from `chown`/`fchown` and a priority raise. Removing the `fchown` check makes the boot-test fail.
- The `AEROS_KILL` check could fail about one run in ten: a timer tick between the probe's `fork` and `kill` let the child run first. It now retries up to five times and fails only if the child wins every time.
- Boot-test no longer races the TCP echo check: the guest prints `AEROS_TCP_LISTENING` and the host waits for it before connecting.
- Deterministic mutation fuzzing of the ELF loader, compatibility inspector, antivirus scanner, image decoders and firewall frame parser runs in every boot-test (`AEROS_FUZZ`); a panic or hang fails the boot.
- New boot-test gates: process ASLR, virtio-gpu, firewall, symlink syscalls.

### ACPI events, battery and thermal
- The system control interrupt (`acpi_events.rs`, vector 54): the kernel switches the platform to ACPI mode, enables the fixed-hardware power button and every general-purpose event the firmware has a handler for (`\_GPE._Exx` edge, `\_Lxx` level), and routes the interrupt through the I/O APIC with the polarity and trigger the MADT gives. The handler only acknowledges registers and sets flags (a level event stays masked until its AML handler has run); the AML runs from `poll`, in thread context. A stuck line is shut off after 4,000 empty interrupts. The power button starts the same animated shutdown as the power menu (`AEROS_POWER_BUTTON`).
- `acpi_devices.rs` reads batteries (`_STA`, `_BIX` or `_BIF`, `_BST`: charge, rate, estimated time, cycles, model), the mains adapter (`_PSR`), the lid (`_LID`) and thermal zones (`_TMP`, `_CRT`, `_PSV`, `_HOT`) through the interpreter; new shell commands `battery` and `thermal`. The interpreter keeps a queue of `Notify` calls the handlers issue.
- Embedded controller (`ec.rs`, `PNP0C09`): the byte-wise read, write and query protocol with bounded waits, `EmbeddedControl` operation regions in the interpreter (two new hooks), `_REG(EmbeddedControl, 1)` after the handler exists, the controller's own event line and `_Qxx` dispatch. Laptop tables keep the battery, adapter and lid behind it. `_INI` of `\_SB` and of every present device now runs at load.
- Tested on the host by `tools/aml-host` against hand-assembled tables (batteries through `_BIX` and `_BIF`, absent and unknown readings, adapter, lid, thermal zones, GPE discovery and `Notify`, an EC-backed region read and written through the hooks, `_REG` and `_Qxx`) and against a model of the controller's host interface (handshakes, query order, a dead controller timing out); in the boot-test `AEROS_ACPI_EVENTS` and `AEROS_POWERBTN` check that QEMU's `system_powerdown`, sent over the monitor, arrives as an interrupt (`test.ps1` now opens a monitor port for that handshake).
- Not done, and not testable in QEMU: a real laptop's battery and EC events have not run; sleep states (S3 needs a safe resume path, so `Sleep` in the power menu still only blanks the screen); CPU frequency scaling; lid-triggered actions.
