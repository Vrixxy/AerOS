# Changelog

All notable changes to AerOS. Versions are not tagged yet; everything below is under Unreleased and grouped by area, newest first within each group.

## Unreleased

### Security review (October 2026)
- Programs started from the Terminal by a user who has not elevated with `ear` (`run`, or a plain command that runs a `/bin` or `/usr/bin` program) start without Linux capabilities, so they can no longer reboot, mount, set the clock, raise priorities, or signal and trace what they did not start. Before, every program had all capabilities and could do what `ear` guards.
- No process may signal a kernel task (`kill`, `tkill`, `tgkill`, `pidfd_send_signal`); a program could kill the desktop before. `process_vm_readv`/`writev` now follow the ptrace rule (own descendants, or `CAP_SYS_PTRACE`); they reached any process's memory. `setpriority` on another task needs the same.
- Protected files: `/data/ACCOUNT.DAT` and the quarantine (`/data/QUAR`) cannot be read, and `/data/AVSIG.DAT`, `/data/AUDIT.LOG` and `/data/MEASURE.REF` cannot be changed, by a program without `CAP_DAC_OVERRIDE` or by an unelevated shell command; the same goes for changes under the system image (which the union root would have let a program replace, ahead of a later `ear` running it), `/home/.root` and `/home/pkg` (the package trust store). The kernel's own bookkeeping (quarantine, audit log) still writes them. The check sits below symlinks and bind mounts. A boot check (`AEROS_PROTECTED_FILES`) proves both refusals and the system path.
- "Forgot password?" on a locked session restarts the machine after removing the account, so the new account does not inherit the running session (its windows, terminal and memory). At the first sign-in after boot it works as before.
- `MAP_FIXED` over existing pages cleared the old translation only after freeing its frame: a failed allocation left a mapping of a freed frame, and threads on other processors were not stopped first.
- Hypervisor (Linux guest): the virtio ring and descriptor accessors now refuse guest addresses outside guest RAM (a guest could make the host write a status byte, or read, anywhere in host memory); the pvclock and wall-clock MSR addresses are checked without overflow; MSRs that reach the host machine (VM_HSAVE_PA, VM_CR, SMM, SYSCFG, HWCR, MTRRs, microcode, TSC, machine-check banks, P-states, the local APIC) are intercepted; VMLOAD, VMSAVE, STGI, CLGI and SKINIT are intercepted, and the guest no longer sees SVM in CPUID.
- FAT volumes: a cluster chain or a directory parent chain that loops no longer hangs `fsck` or a rename.
- Follow-ups from the review's open list: `execve` and the shell's program launcher now need an execute bit (FAT volumes have no modes and are scanned instead); the failed-sign-in count and any wait are saved in `/data/LOCKOUT.DAT` and survive a restart, so rebooting is no way past the throttle; the Linux guest's SPEC_CTRL and PRED_CMD writes are intercepted; swap pages are encrypted (ChaCha20, a key that exists only in memory, a new nonce for every write), so nothing readable is left on the swap partition or in a freed slot.
- An intermittent boot-test failure (`AEROS_VM_LINUX source=none`) is fixed: the hypervisor's three boot checks each took 32 MiB of contiguous, 2 MiB-aligned memory and its control pages and never gave them back, so with some random kernel placements there was no room left for the third guest. Each guest's memory is now released after its run.
- Ping sockets: `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` sends the echo requests a program writes (the identifier becomes the socket's, the checksum is filled in) and receives the replies, as Linux's unprivileged ping sockets do; an echo to this machine is answered at once. They share the UDP port table as a separate kind of binding, so UDP datagrams never reach them. Boot check `AEROS_PING_SOCKET` pings this machine and the QEMU gateway through the socket layer. Raw sockets are refused with `EPERM`, as Linux refuses them without `CAP_NET_RAW` (Debian's BusyBox `ping` has no ping-socket fallback, so it reports that it is not root).
- `ptrace` attach never reaches a kernel task (an elevated program could stop the desktop).
- The boot fuzzer also damages AerFS volumes (120 rounds: random sectors, and superblock fields with the checksum made valid again) and mounts, lists, reads, writes, removes and checks them.
- `socketpair(AF_UNIX, SOCK_DGRAM | SOCK_SEQPACKET)`: pairs that keep message boundaries (each write is one read, a short buffer drops the rest of its message, more than 4000 bytes is `EMSGSIZE`); boot check inside the socketpair self-test.
- `socket(AF_UNIX, SOCK_SEQPACKET)` with `bind`/`listen`/`accept`/`connect`: the connection keeps message boundaries, and a stream client cannot connect to a sequenced-packet listener (`ECONNREFUSED`, as on Linux); boot check inside the AF_UNIX socket self-test. `getsockopt(SO_TYPE)` on an AF_UNIX socket now reports its real type (it always said stream).
- `socket(AF_UNIX, SOCK_DGRAM)`: `bind` a name, `sendto` a name, or `connect` and `send`; a write before `connect` is `ENOTCONN`, and once the receiver closes its name is free and its peer gets `ECONNREFUSED`. BusyBox `syslogd` + `logger` over `/dev/log` is in the apps gate.
- `recv`/`recvmsg` with `MSG_PEEK` on AF_UNIX sockets (it was `EOPNOTSUPP`). A Perl probe (Socket module: `socketpair`, `MSG_PEEK`, a datagram socket bound and sent to by name) is in the apps gate.
- `execve` takes up to 64 argv and 64 environment strings sharing 12 KiB, any one of them as long as fits; it was 24 strings of at most 383 bytes each, so a longer `sh -c` script or a fuller environment failed with `E2BIG`. The copies also take less of the syscall stack than before (12 KiB instead of 18).
- Room for more IPC at once: 32 pipes (was 8, system-wide), 32 AF_UNIX connections or datagram sockets (was 8) 16 bound AF_UNIX names (was 4) and 32 epoll instances (was 8). The tables are reset in place rather than by assigning a fresh copy, which with the larger sizes could otherwise build a large temporary on the stack.
- The Terminal runs programs interactively: a command that starts a program from `/bin` or `/usr/bin` (a name the shell does not know itself, or a path; no pipe or redirection) runs as a foreground job, its output appears as it is written (a prompt without a newline, such as Python's `>>> `, shows as the last line), each line typed goes to its input, Ctrl+C sends SIGINT and Ctrl+D ends its input, and there is no time limit. The desktop keeps running meanwhile (it used to wait up to twenty seconds with the program given no input). Input is a pipe, not a terminal, so interactive programs need their interactive switch: `python3 -i`, `bash -i`. Checked at boot by `AEROS_TERMINAL_JOBS` (`/bin/cat` echoes a line and ends with its input, `/bin/sleep 30` ends at Ctrl+C).
- Debian's Python 3.13 runs natively (`python3 --version`, a standard-library script, files, `subprocess`; in the apps gate). It is a fixed-address program with an interpreter, which `execve` now loads (only position-independent programs could have one). `tools/make-python-userspace.ps1` extracts it from the Linux guest's root filesystem with 7-Zip and writes `kernel/src/initramfs_python.rs` (545 files, 28 MiB: the standard library without byte-code caches, tests, Tk, IDLE and its LICENSE.txt, with OpenSSL, SQLite, readline and the CA bundle for `ssl`, `hashlib`, `sqlite3`, `readline` and `curses`).
- Bigger processes. A process's record of its pages now lives in its page-table entries (bits the processor ignores hold a mapping's protection and sharing, an image page's attributes; swapped pages keep their flags), so the record is a few dozen bytes instead of about 50 KiB copied around by value, and the window can grow: 256 MiB per process (image 16 MiB, heap 32 MiB, stack up to 8 MiB, about 200 MiB of mappings), and 128 MiB for a fixed-address program (about 72 MiB of it for mappings: Python maps libcrypto, libssl and the rest there). `execve` takes the new image's frames as a chain threaded through the frames themselves instead of five page-sized arrays on the stack. `bzip2` at its default block size works now, and Perl builds a 20 MB string (both in the apps gate).
- The process memory pool is a bitmap over up to 16 blocks of RAM (a quarter of the memory, up to 1 GiB) instead of a list of free ranges, which silently lost a page whenever more than 512 separate free ranges built up. The kernel keeps out of the first 128 MiB (allocator and image placement), and the AML interpreter and the sleep code reach firmware memory there through the kernel's own page tables (`paging::with_kernel_tables`), so OVMF's ACPI NVS in that range no longer rules fixed-address programs out.
- Private anonymous mappings are demand-zero, as on Linux: a page gets its frame when it is first touched (by the program, or by a system call filling a buffer there), and a `PROT_NONE` page is only a reservation (touching it is a fault, where it used to be readable). `madvise`, `msync` and `mincore` check the range without touching it. glibc reserves 64 MiB per thread arena this way, which with every mapped page backed at once drained the pool as soon as there was room to map it (Debian's multithreaded `xz` failed with "Cannot allocate memory").
- `tools/test.ps1` waits up to 720 s for the ready state (was 480 s; a loaded host slows the guest by up to 5x) and runs the machine with 1 GiB (was 512 MiB): the kernel now keeps out of the first 128 MiB and the image carries Python, and the hypervisor's boot checks need large contiguous blocks besides the process pool, which leaves at least 128 MiB to the rest of the system.
- `poll`/`epoll` report `POLLHUP` on a pipe whose writers are gone and on a socket pair whose peer closed, and `POLLERR` on a pipe whose readers are gone, whether asked for or not, as Linux does (Python's `subprocess` waits for exactly that). The ELF parser's own image limit had stayed at the old 6.25 MiB.
- TCP: 64 KiB send and receive buffers per connection (was 8 KiB), so up to 64 KiB is in flight per round trip, and Nagle's algorithm as on Linux (a partial segment waits while data is unacknowledged; `TCP_NODELAY` turns it off), checked by a new `nagle` case in the TCP engine self-test. Connection slots are no longer `Copy` and are reset in place: `close` used to copy a whole slot onto the stack. `tools/tcp-host` runs the same engine self-test on the host in a fraction of a second (`cargo test --release`).
- `/tmp` holds big files: the kernel heap, where the tmpfs keeps files bigger than a page, is an eighth of the usable memory (16 to 256 MiB; it was 16 MiB), and a file may grow to 1 GiB (it was 4 MiB). Python round-trips a 20 MB file there and runs SQLite on a file database (byte-range locks, `pread`/`pwrite`, `fsync`) in the apps gate.
- `tools\run.ps1` boots again. With Python embedded, `build\esp` (the image plus the Linux guest's 420 MB `ROOTFS`) passed the 516 MB QEMU can make a FAT drive of, so QEMU refused to start; `tools\esp-drive.ps1` now boots `run.ps1`, `capture.ps1`, `live-qemu.ps1`, `live-gl.ps1`, `live-linux.ps1` and `test-install.ps1` from a copy without `ROOTFS` when it is too big (the guest uses `build\rootfs-disk.img`), bringing what the last session wrote back to `build\esp` first. `build.ps1` returns only the ESP path (its helpers' output used to come back with it and garble the QEMU drive argument). `capture.ps1` can type into the program a command started (`-Then`, `-SettleMs`).
- A 512 MiB machine boots normally again: the process pool leaves 128 MiB of what the frame allocator really has (it counted the first 128 MiB, which the allocator never hands out, and left the kernel 6 MiB), and the kernel heap is held to half of what is left. An ordinary boot no longer runs the 156 real programs of the apps gate (minutes of Python, git and big files before the desktop); the boot test still does.
- The Terminal's foreground programs run on a terminal (`syscall/tty.rs`): their input and output pipes belong to a TTY, so `isatty` is true, `stdout` is line-buffered, and termios, window-size and foreground-group ioctls work. What is typed goes through a line discipline: canonical mode echoes, erases, delivers a line at a time and makes Ctrl+D one end of file (a program can read again afterwards); Ctrl+C and Ctrl+\ signal the foreground process group; a program that switches to raw mode (Python's `tty.setraw`, readline, `read -s` with echo off) gets every key as it is pressed, arrows and Delete as escape sequences. Interactive programs no longer need `-i`. The Terminal shows what is typed on the program's own prompt line, hides it while echo is off, and follows carriage returns, backspaces and the cursor, erase, insert and delete sequences line editors send. `AEROS_TTY` checks the line discipline alone; `AEROS_TERMINAL_JOBS` adds `[ -t 0 ] && [ -t 1 ]` under BusyBox `sh` and Python reading three keys in raw mode.
- `setrlimit`/`prlimit64` work for every resource: each process keeps its own soft and hard limits (inherited across `fork`), a soft limit moves freely up to the hard one, and a hard limit can be lowered and raised back only with `CAP_SYS_RESOURCE`. Every resource but `RLIMIT_NOFILE` was refused with `EPERM` (`setrlimit(RLIMIT_CORE, 0)` is common), and `prlimit64` handed back the new limit where Linux returns the old one. A Python probe (core and stack limits, `prlimit` returning the old value, `EMFILE` past a lowered `RLIMIT_NOFILE`) is in the apps gate.
- Up to 64 tasks (processes and threads) at once, was 32: a program with a few dozen threads, or a pool of worker processes, ran out of slots. The scheduler's table is reset in place. `getrlimit` reports a 1 MiB stack (512 KiB before; glibc makes each thread's stack that size, and a fixed-address program has 72 MiB for all its mappings) and the real process window (256 MiB) as `RLIMIT_AS` instead of 12 MiB. A Python probe running 40 threads at a barrier is in the apps gate.
- Pipes and AF_UNIX stream connections hold 64 KiB, as on Linux (they held 4 KiB). A write of up to 4 KiB (`PIPE_BUF`) goes in whole or waits, a blocking write to a pipe or stream socket returns only once all of it is in (or a signal or the reader's close stops it), and `poll` reports a pipe writable when 4 KiB fits. The rings live outside the pipe records, so a record is small to copy; `read` and `write` move 4 KiB per step instead of 256 bytes. The pipe self-test fills a pipe, checks that a 2000-byte write is refused whole and a 5000-byte one is cut to what fits; a Python probe (one 64 KiB `os.write` into an empty pipe, `EAGAIN` when full, and 1 MiB through `cat` with `subprocess.run`) is in the apps gate. `ioctl` takes `FIONBIO`, `FIOCLEX` and `FIONCLEX` on any descriptor and `FIONREAD` on a pipe (Python's `os.set_blocking` uses `FIONBIO`; it was `ENOTTY`).
- A tmpfs file that cannot grow because the kernel heap is used up fails with `ENOSPC` (it said `EFBIG`, which means the file size limit), and when doubling the file's block does not fit, the exact size is tried.
- POSIX shared memory: `/dev/shm` is a directory of memory files (it lives at `/tmp/.dev/shm`), and a file there mapped `MAP_SHARED` is the same frames in every process that maps it (`syscall/posixshm.rs`, found by inode; what a mapping writes is not written back to the file). `link` works inside `/dev/shm`, as much as `sem_open` needs (elsewhere it stays `EPERM`), and futexes that are not `FUTEX_PRIVATE` in a shared mapping are keyed by physical address, so a process-shared semaphore posted in one process wakes another. Python's `multiprocessing.Pool` and `asyncio` (client and server over loopback) are in the apps gate.
- `recv` and `recvfrom` take a buffer bigger than one call fills (asyncio reads into 256 KiB; it was `EFAULT` past 64 KiB, and past 1472 bytes for UDP). `read`, `write`, `pread`, `pwrite`, `getrandom` and the device reads check the whole buffer against the process's address range, as Linux's `access_ok` does, and then only the part one call moves, instead of making every page of a large buffer present first.
- The table that counts the owners of shared frames (copy-on-write after `fork`, program pages, shared mappings) never removed an entry, only marked it reusable, so once it had filled up over a boot every lookup of a frame not in it (every private page given back) walked all 8192 slots. Entries now go when their count does and the ones after them move up, and the table has 32768 slots. The benchmark that maps, touches and unmaps 8 pages went from about 200 µs to about 6 µs.
- The bigger process windows cost less: walks over the mapping area (`fork`, `exec`, exit, `/proc` maps, swap) stop at the highest page ever used, the search for free mapping space starts at a hint below which everything is used, small mappings (16 pages or fewer) get their frames at once, and a process's page tables are not wiped on release (only its stack is).
- TCP `bind` to port 0 picks the ephemeral port right away, as Linux does (it was left to `listen`, so `getsockname` in between, which Python's `http.server` does, reported port 0), and a socket that is bound but not listening now holds its port against the next ephemeral pick. A Python probe runs `http.server` on a thread and fetches from it over loopback.
- UDP: 16 sockets (was 8), 16 queued datagrams per socket (was 4) and 40 port bindings (was 24); bindings are reset in place too.
- Fixes found on the way: `send`/`recv` (`sendto`/`recvfrom` without an address) on any AF_UNIX socket returned `EBADF`; a blocking read or write on an AF_UNIX socket gave up with `EAGAIN` after 64 yields instead of waiting (it now waits like a pipe and stops for a signal); `SOCK_NONBLOCK` on AF_UNIX `socket`/`socketpair` was ignored; `read`/`write` on a datagram or sequenced-packet socket split messages longer than 256 bytes.
- `tools\boot-linux.ps1` boots from a drive without `ROOTFS` when `build\esp` is too big for QEMU's 516 MB FAT volume (it had stopped working since the image grew).
- Second pass (drivers and parsers). The kernel is built with overflow checks, so an overflow on outside input is a kernel panic; these were reachable:
  - USB HID: a report descriptor with fields wider than 32 bits, or huge report sizes and counts, panicked the kernel when the device was plugged in or sent a report. The boot fuzzer now also runs mutated HID and configuration descriptors through the same parsing (20,000 rounds); its first run found one more (sign-extending a 31-bit field). A pointer reporting huge motion or wheel values no longer overflows the pointer position or the scroll arithmetic.
  - AerFS: a volume whose superblock or inode claimed a tree taller than three levels panicked on mount (scratch index, `capacity` overflow); a block referenced twice (a looping tree) is now corruption instead of a near-endless walk.
  - Programs: `mremap` with sizes near 2^64, a signal delivered with the stack pointer just above zero, and interval timers with huge periods each panicked the kernel.
  - Network cards (virtio-net, e1000, RTL8168): a received length larger than the receive buffer is no longer copied past it.
  - `acpi eval` and `acpi crs` run firmware methods that drive the hardware (port, memory and PCI writes); they now need `ear`.

### Desktop (Figma update of October 2026)
- The feather (leaf logo) sits at the top left of the bare desktop and opens the system menu (also the F key): Parcel, Settings, Store, Recent Apps (the app switcher), Quit all apps, Shutdown, Restart, Sleep. A gear at the top right toggles the quick settings. Both hide while a window or the launcher is open (`desktop_menu.rs`).
- Parcel is the file-share panel: a black rounded card with four "Person" circles and an "Upload your file" tile (Upload opens Files). It is the design only: there is no device discovery yet, so a person reports that nothing was found nearby.
- The clock and date in the dock are white, on a darker glass capsule. A boot self-test clicks the feather, opens Parcel, toggles the gear and quits all apps.

### Sign-in and windows
- The lock screen no longer swallows keystrokes: any key wakes it and a typed character becomes the first character of the password (before, keys that mapped to no shortcut were dropped, so a password typed straight onto the lock screen arrived missing its first characters and could never match). A boot self-test types a password straight onto the lock screen. The password fields on the sign-in and setup screens have a show/hide eye (click it, or press the Up arrow).
- Several apps can be open at once: windows that are minimized or switched away from stay open (dock dot under the icon), the close button really closes, and Alt+Tab (Alt+Shift+Tab backwards) opens a switcher of the open apps; releasing Alt, Enter or a click picks one, Esc cancels.
- Settings is a real app now (`desktop_settings.rs`): Network (status, address, Wi-Fi), Display (brightness slider, cursor and glass path), Sound (volume slider, mute), Keyboard (pick the layout, saved), Time (time zone list, automatic time), Power (lock, sleep, restart, shut down) and About. Tab/arrows/Enter work as well as the pointer. Keys typed during the boot splash still reach the lock and sign-in screens.
- Forgot-password recovery: the sign-in screen has "Forgot password?" (or the Down arrow) with a confirmation; resetting deletes the saved account and starts setup again, files are kept, and it is written to the audit log. This machine has no disk encryption, so it gives no one anything physical access did not already. Settings gained an Account page (user name, lock, change password opens the terminal with `passwd` typed).
- A "Caps Lock is on" warning replaces the hint on the sign-in screen and under the setup fields while Caps Lock is on.
- `virtio_rng.rs`: virtio-rng driver feeding the host's entropy into the random pool (`AEROS_VIRTIO_RNG`, `random::add_entropy`).
- Files, Notes and Trash work from the keyboard (`desktop_files.rs`): arrows move the selection, Enter opens (folders navigate, text files open in the Notes editor and save back to where they came from), Backspace goes up, Delete removes, F2 or the Rename button renames in place (existing names are never replaced). A click selects and a double click opens. Notes lists open on Enter (or start a new note when nothing is selected) and Delete removes; Esc in the note editor now saves instead of throwing the edit away. Trash rows show the selection; Enter restores and Delete removes for good. Files has a Media place for removable drives (`/media`). The Delete key and F2 are new `DesktopKey`s and Backspace now reaches non-text screens. A boot self-test renames, opens, edits and saves a real file. Ctrl+C / Ctrl+X / Ctrl+V set a file aside, move it or place a copy in the folder being shown (a name already in use is refused; folders can be moved, not copied).
- Fixed: with Settings (or the browser) open, clicking a dock icon did not launch the app (the click was delivered as Enter to the open window, toggling Wi-Fi in Settings). Dock clicks now launch directly; the dock highlights the active app instead of the last clicked icon, and Settings gets its running dot. The boot-time Shield self-test no longer shows a "Quarantined EICAR-Test-File" toast on every start. Sign-in hints sit on a soft chip so they stay readable over the snow; Settings shows the CPU model name, the Time toggle label fits, and the Files status line is darker.

### Linux syscalls
- 34 more: `getdents`, `link`/`linkat` (EPERM: the filesystems have no hard links), `syslog` (the kernel log), `setreuid`/`setregid`/`setresuid`/`setresgid`/`setfsuid`/`setfsgid` (only uid/gid 0 is accepted, as with `setuid`), `rt_sigpending`, `rt_sigtimedwait`, `rt_sigqueueinfo`, `rt_sigsuspend`, `utime`/`utimes`, `mknod`/`mknodat` (regular files only), `sched_setparam`, `sched_rr_get_interval`, `setrlimit`, `readahead`, `sync_file_range`, the xattr family (EOPNOTSUPP), `restart_syscall`, `inotify_init`/`inotify_init1`/`inotify_add_watch`/`inotify_rm_watch`, `sendmmsg`/`recvmmsg`, `openat2` (no resolve restrictions). The boot test checks the pointer-free corners (`AEROS_SYSCALL_MISC`); the syscall fuzzers skip the ones that block or signal.
- inotify reports events (`syscall/inotify.rs`): an instance is a byte pipe the kernel fills with `inotify_event` records; a watch on a file or directory sees open, close, modify, attrib, create, delete, move (with cookie) and, for the watched object itself, delete/move self. Up to 32 watches. Events are raised by what processes do through the syscall layer, so changes made by the desktop or the shell are not seen, and consecutive identical events are not merged. `aeros-sysx` creates a file under a watched directory and reads the record (`inotify_event`).
- Ten more small ones: `preadv2`/`pwritev2` (flags are hints; offset -1 uses the file position), `epoll_pwait2`, `mlock2`, `unshare` (0 only; namespaces are EPERM), `setns` (EPERM), `sched_setattr`/`sched_getattr` (SCHED_OTHER only), `futimesat`, `rt_tgsigqueueinfo`. `execveat` (a path that is absolute or relative to the working directory, or AT_EMPTY_PATH for `fexecve`; `aeros-sysx` re-executes itself both ways). `pidfd_open` (a descriptor that polls readable once the process has ended) and `pidfd_send_signal`; `process_vm_readv`/`process_vm_writev` (any live process; `aeros-sysx` reads and replaces a forked child's buffer). Still without a number: `fanotify`, `userfaultfd`, `bpf`, `perf_event_open`, `io_uring`.
- Also `mremap` (grow by moving with MREMAP_MAYMOVE, shrink in place), `splice` (file or pipe in, pipe or file out), `tee`, and `signalfd`/`signalfd4` (a descriptor that reads and consumes pending signals). A new userspace program, `aeros-sysx`, calls all of these with real user pointers at boot (`AEROS_SYSX`, one `AEROS_SYSX_STEP` line each).
- POSIX timers: `timer_create` (SIGEV_SIGNAL, SIGEV_NONE, SIGEV_THREAD_ID; up to 8 per process, on the realtime, monotonic and boot-time clocks), `timer_settime` (relative or absolute, periodic), `timer_gettime`, `timer_getoverrun`, `timer_delete`. Expiry raises the chosen signal like `alarm` does; timers are not inherited by `fork` and are deleted by `exec`. `sigev_value` is not passed on. The `alarm`/`setitimer` expiry now leaves the signal pending when it is blocked (a blocked SIGALRM with the default action used to end the process anyway), and `rt_sigtimedwait` sees timer signals.
- System V IPC (`syscall/sysv.rs`): message queues (`msgget`, `msgsnd`, `msgrcv` with type selection and MSG_EXCEPT/MSG_NOERROR, `msgctl` RMID/STAT/SET; 4 queues of 16 messages up to 512 bytes) and semaphore sets (`semget`, `semop`, `semtimedop`, `semctl` GETVAL/SETVAL/GETALL/SETALL/STAT/RMID; 4 sets of up to 16, atomic multi-operation, blocking with EINTR/EIDRM). The tables are kernel-wide so unrelated processes share them by key. SEM_UNDO is accepted and not undone at exit.
- Shared memory: `MAP_SHARED|MAP_ANONYMOUS` mappings and System V `shmget`/`shmat`/`shmdt`/`shmctl` (4 segments of up to 64 pages). Shared pages stay writable across `fork` (the child sees the parent's writes and the reverse) instead of becoming copy-on-write; they are skipped by swap while another process holds them, and a removed segment is freed when its last attach goes (also when the attaching process just exits). `/proc/<pid>/maps` marks them `s`. `vmsplice` copies through a pipe (no page gifting). `shmat` takes no address hint; `MAP_SHARED` on a file is accepted read-only only (a writable one would have to reach the file). The `aeros-sysx` steps `map_shared_fork` and `shm_fork` check it with a real `fork`.
- `siginfo` (the handler's second argument and the `signalfd` record) carries `si_code` and `si_pid` for `kill`, the value and code of `rt_sigqueueinfo`, and for POSIX timers `SI_TIMER` with the timer id, overrun and the `sigev_value`; alarm and the CPU timers give `SI_KERNEL`. `si_uid` is 0.
- Faults in user mode (page fault, divide error, invalid opcode, alignment) now run the process's own `SIGSEGV`/`SIGFPE`/`SIGILL`/`SIGBUS` handler when it has one and the signal is not blocked, with `si_addr` and `si_code` (SEGV_MAPERR/ACCERR) in the `siginfo`; before, every such fault ended the process. A handler that returns re-runs the instruction, as on Linux. `SA_ONSTACK` runs a handler on the `sigaltstack` (what a stack-overflow handler needs) and `SA_RESETHAND` puts the default action back when it is taken; `aeros-sysx` checks both from a faulting child. A runtime's default handler (Rust's, for stack overflow detection) therefore sees faults first: a traced process's injected fault signal reaches it before the process dies, so the ptrace probe sees one more stop.
- Fixed: `kill` on yourself ignored the signal mask and ended the process even with the signal blocked. A blocked signal now stays pending (visible through `rt_sigpending`, taken by `rt_sigtimedwait`/`signalfd`), and its default action runs when it is unblocked.

### /proc and the in-memory filesystem
- `/proc/net/dev` (loopback and the primary interface, with real frame and byte counters from `nic`). The in-memory filesystem's pools went from 56 mutable files and 96 nodes to 112 and 256: the generated `/proc` entries (self, per-process files, the descriptor links) had filled the old pool and the signed-update self-test could no longer create its scratch files. `ls /proc` creates only a directory per process; its files are written when it is looked at.

### Child exit
- A write to a pipe that has no reader raises SIGPIPE as well as failing with EPIPE (the default action ends the process, as in `yes | head`; a handler or SIG_IGN, which the Rust runtime sets at start, only sees the EPIPE).
- A parent gets SIGCHLD (with `si_pid` and the exit status) when a child ends; the default action ignores it, so only a program with a handler sees it. `wait4` also ends with EINTR when a caught signal arrives while it waits for a child that is still running. `aeros-sysx` installs a handler, lets a child end and checks the pid it was given.

### More real programs: Perl, git, make, tar and a threaded glibc test
- **Debian's Perl** (`/usr/bin/perl` and perl-base: `strict`, `warnings`, `POSIX`, `List::Util`, `File::*`, `Getopt::Long`, `Cwd`, `IO::*`, ...) runs: expressions, regexes, hashes, files, backticks and `system`. **`git`** runs: `init`, `add`, `commit`, `log`, `status`, `cat-file`. So do `make`, `tar`, `awk` (mawk), `patch`, `cmp`, `diff`, `xz`, `bzip2`, `less`, `nano` and `vi` (version checks for the editors; there is no terminal for them yet). `bash` is also `/bin/sh`, so `system()`, `popen()` and scripts work. The boot gate runs 135 command lines. `tools/make-gnu-userspace.sh` and `tools/make-perl-userspace.sh` bring the programs and libraries from a Debian; `tools/build-dyntest.sh` builds `userspace/dyntest/dyntest.c`, a glibc program that checks threads (mutex, condition variable), `fork`, pipes, `posix_spawn`, `system`, signals (including `alarm`), `dlopen`, shared memory, loopback TCP between threads, `poll`, `epoll`, `timerfd`, `eventfd`, directory listing and more.
- Python is not in: Debian's `python3.13` is a fixed-address (non-PIE) 11 MiB program, which needs a bigger low-memory window than the machine can promise (the first 8 MiB must be plain RAM; ACPI data sits just above).
- A process window is eight page tables (16 MiB): image area 6.25 MiB, heap 512 KiB, a stack that grows to 784 KiB, then the mapping area (8.5 MiB; a fixed-address program keeps its 8 MiB window with a 488 KiB mapping area). The memory every process takes its pages from is a third of the usable memory (16 to 128 MiB; it was a fixed 16 MiB, which a handful of dynamically linked processes used up). Syscall stacks are 256 KiB. The advertised `RLIMIT_STACK` is 512 KiB (glibc sizes each thread's stack from it) and `RLIMIT_AS` 12 MiB.
- The in-memory filesystem: a file outside `/data` can be up to 4 MiB (it moves to the kernel heap once it passes 4 KiB; before, 4 KiB was the limit, which broke `tar`); a file that is removed (or replaced by a rename) while open stays usable until it is closed (`git` unlinks its lock files that way); node pool 768.
- `fcntl`: `F_SETFL` ignores the flags it cannot change (a program passes back what `F_GETFL` returned, access mode included), record locks are granted, `F_GETPIPE_SZ`/`F_SETPIPE_SZ` answer 64 KiB; `chmod`, `fchmod` and `mkdir` ignore mode bits beyond the permissions.

### Dynamically linked programs: Debian's bash and GNU tools run
- **Programs that need `ld.so` and shared libraries now run.** `execve` reads the program's interpreter path (`PT_INTERP`), loads the interpreter into the same window as the program, starts it with the usual auxiliary vector (`AT_BASE`, `AT_ENTRY`, `AT_PHDR`, ...) and `ld.so` maps `libc.so.6` and the other libraries itself with `mmap`. The boot gate runs Debian's own `bash` and 60 GNU programs (`ls`, `cat`, `cp`, `mv`, `sort`, `uniq`, `tr`, `sed`, `grep`, `gzip`, `find`, `xargs`, `du`, `df`, `stat`, `od`, `base64`, `dd`, `date`, `env`, ...) from a Debian system, unmodified, with their libraries (`libc`, `libselinux`, `libpcre2`, `libacl`, `libtinfo`, `libgmp`, ...): 118 command lines in all with the BusyBox ones (`AEROS_APPS done passed=118 total=118`). `tools/make-gnu-userspace.sh` copies the programs and libraries from a Debian and writes `kernel/src/initramfs_gnu.rs`. A dynamically linked program can only be started by `execve` (not by the shell's `run`), and the interpreter and libraries come from the initramfs.
- A process window is six page tables (12 MiB) instead of four: the mapping area moved to the end of the window and grew from 768 KiB to 4.8 MiB (a fixed-address program keeps its 8 MiB window and a 872 KiB mapping area, because the rest of its address space is the kernel's identity map). Syscall and interrupt stacks are 224 KiB (the address-space structure is about 33 KiB and is copied by value).
- `mmap` takes an address with `MAP_FIXED` (replacing what is there) and `MAP_FIXED_NOREPLACE`, ignores a hint without them, and accepts `MAP_DENYWRITE`, `MAP_NORESERVE` and `MAP_POPULATE`; `munmap` of pages that are not mapped is not an error; `PROT_NONE` reservations work (the pages stay readable, which no program relies on).
- File-descriptor and path details real programs depend on, all found by running them: an `int` argument arrives zero-extended from glibc, so `AT_FDCWD` (-100) and the "no file" descriptor (-1) of an anonymous `mmap` were not recognised; `openat`/`fstatat`/`statx` work relative to a directory descriptor (the path the directory was opened with is remembered per descriptor), `statx` accepts `AT_NO_AUTOMOUNT` and the sync flags and no longer ignores `AT_SYMLINK_NOFOLLOW`, `O_PATH` is a plain open, `read` and `write` of more than 64 KiB transfer 64 KiB instead of failing with EFAULT (what `cat`, `grep` and `gzip` do with their 128 KiB buffers), and close-on-exec descriptors are closed properly when a program is executed (a pipe end that was only dropped kept the pipe open: `xargs` waited forever for its child to start).
- Argument lists of up to 24 strings of 383 bytes (was 16 of 95), the startup stack takes 24 arguments and 24 environment strings.

### Real programs: BusyBox runs
- **Debian's BusyBox 1.37 (a static, non-PIE glibc build that is not ours) runs on AerOS**, 30 command lines in a boot gate (`aeros-apps`, `AEROS_APPS done passed=30 total=30`): `echo`, `uname`, `cat`, `ls -l`, `find`, `ps` (walks `/proc`), `free`, `uptime`, `date`, `grep`, `sed`, `awk`, `md5sum`, `sha256sum`, `wc`, `sleep`, shell arithmetic, loops, pipelines (`tr`, `sort`, `head`, `gzip | gunzip`), subshells, background jobs and exit statuses. What it took:
  - A process window is four contiguous page tables (8 MiB: a 6.25 MiB image area, then heap 512 KiB, mappings 768 KiB, stack growth 384 KiB) instead of one (2 MiB). It was 2 MiB before, which no 2 MB program could fit.
  - Fixed-address (`ET_EXEC`, linked at 0x400000) programs: their window is at virtual address 0, in a private copy of the identity map's first GiB; the kernel keeps reaching physical memory through the rest of it. This needs the first 8 MiB of memory to be plain RAM (the boot code checks the firmware map and the kernel image: `AEROS_LOW_WINDOW clean=`), so the frame allocator never hands out memory below 8 MiB, and a machine whose map is not clean (ACPI data below 8 MiB) simply refuses such programs. `execve` can switch a process between the two kinds of window.
  - `mprotect` works on program-image pages (RELRO), the stack grows several pages at once (a big frame in `grep`), `open` accepts `O_NONBLOCK`, `O_NOFOLLOW` and the like, program loading follows symbolic links, and a new program starts with every register clear (`rdx` is the `atexit` function: a leftover pointer there was called at exit).
  - An exited child stays a zombie until its parent waits for it (a shell waiting for two pipeline children lost the second one's status: it reported 255).
- **The wider sweep: 91 command lines pass** (`AEROS_APPS done passed=91 total=91`): mkdir/cp/mv/ln/chmod/find/du/df, tar, cpio, gzip, xz, base64, od, hexdump, sort, awk, sed, xargs, diff, dd, mktemp, tee, top, ps, ping, shell functions, traps, here-documents and more, plus Debian's `ldconfig` (a static-PIE glibc program). Kernel gaps it found and closed:
  - `/dev`: `/dev/null`, `/dev/zero`, `/dev/urandom`, `/dev/random`, `/dev/tty`, `/dev/console`, `/dev/stdin`, `/dev/stdout` and `/dev/stderr` exist and work (there was no `/dev` at all, so every `2>/dev/null` failed). They are listed and `stat`able through the same hidden-directory mapping as `/proc`; opening them gives a descriptor of the device kind.
  - A directory descriptor of `AT_FDCWD` passed as a 32-bit `-100` (what glibc does) was taken for a bad descriptor, so every relative-path `fstatat` failed: `tar`, `gzip` and `cpio` could not see their files.
  - `execve` took only 95 bytes per argument and 16 arguments (now 383 and 24); `mkdir` on an existing directory under a read-only parent said permission denied instead of "exists" (`mkdir -p /tmp/x` failed); `open` refused file-type bits in the mode (`cp` passes the source's `st_mode`); `futimens` was refused; the in-memory filesystem pools grew again (176 files, 384 nodes).
  - Not working: `bzip2` at its default block size needs more memory than the 768 KiB mapping area of the window.
  - The Shield (the exec guard) blocks any program containing both `wget ` and `| sh` (also `curl `, `base64 -d` with `| sh`), so the probe avoids those strings.
  - Syscalls and interrupts run on a 160 KiB stack (was 48 KiB): the process-creation paths copy address-space structures of about 21 KiB, and the overflow wrote into the neighbouring task stack.

### Pipes
- A blocking `read` or `write` on a pipe (or eventfd, signalfd, timerfd, inotify descriptor) now waits for data, space or the end of the stream and ends with EINTR when a signal is pending; before it gave up with EAGAIN after 64 yields, which real programs treat as an error. `O_NONBLOCK` (`pipe2` flag or `fcntl`) keeps the short wait and EAGAIN. Callers inside the kernel stay non-blocking. The bench probe's child closes the pipe ends it does not use, as a correct program must.

### CPU time
- `/proc/<pid>/stat`, `status`, `comm` and `cmdline` work for any live process, not only the caller (filled from the task table; `ls /proc` lists the live pids), so `ps`-style programs that walk `/proc` find them. `maps` and `statm` work for them too; the capability lines are the caller's only. `/proc/self/cwd` (link), `limits` and `cgroup` exist. `/proc/self/fd` has a link per open descriptor (a path, `pipe:[n]`, `socket:[n]` or `anon_inode:[kind]`) and `readlink` follows `/proc` paths. `/proc/self/exe` (`readlink`) names the program the process was started or last exec'd from (it always said `/bin/init`); a forked child keeps its parent's.
- `setitimer`/`getitimer` take ITIMER_VIRTUAL (user CPU time, SIGVTALRM) and ITIMER_PROF (user plus kernel, SIGPROF) besides ITIMER_REAL; they are cleared in a forked child and kept across exec.
- Shell: `top` lists the processes by CPU time with their share (COMMANDS=94).
- Processes are charged CPU time by the timer tick (user or kernel by where the tick caught them, sampled per processor, threads summed into the process). `getrusage` (self, thread, children: a child's time, and its own children's, is added when it is waited for), `times` (including cutime/cstime) and `CLOCK_PROCESS_CPUTIME_ID`/`CLOCK_THREAD_CPUTIME_ID` report it instead of zeros and elapsed time. `/proc/self/stat` has utime/stime and `ps` a CPU ms column. `aeros-sysx` spins in user mode and checks all three syscalls (`cpu_time`). `vmsplice` is there too.

### Software volumes
- `raid.rs`: linear, stripe and mirror volumes over any block disks, as `block::Disk::Volume` (`md0`, `md1`); a mirror keeps serving with a member gone and resynchronises a replacement. Shell command `raid`. Each member keeps a header in its last sector; volumes are assembled at boot from the headers (a member that missed a change is left out as failed), and `raid create` needs `--yes` because it writes one. `lsblk` lists the volumes with their level. Boot gate `AEROS_RAID`. See `docs/RAID.md`.

### Sleep
- Every driver has a resume step now (`sleep::resume_drivers`, called by `suspend` after the processors restart): AHCI, NVMe, virtio block/net/input/gpu, xHCI (devices enumerated afresh), e1000, RTL8139, RTL8168, Intel HDA, AC'97, the SD host controller and the PS/2 controller. Each resets its hardware and programs it again over the memory it already owns. The boot test gate `AEROS_DRIVER_RESUME_TEST` runs the same restart on a live system and does real I/O on every present device afterwards. See `docs/SLEEP.md`. The PCI headers are saved and restored around a sleep too (`AEROS_PCI_RESTORE` damages an idle device's BAR and checks it comes back).

### Screen buffers
- The four full-screen buffers (composed desktop, shadow, wallpaper cache, panel cache) are allocated at boot for the real screen size instead of four static 1080p-sized arrays: about 17 MiB less memory at 1280x800, and screens above 1080p are drawn off-screen like smaller ones (they used to be drawn straight into the framebuffer, whose reads are slow on real hardware). `AEROS_SCREEN_BUFFERS` logs the size.

### Terminal
- A command the shell does not know runs the program of that name from `/bin` or `/usr/bin` (or a given path), static or dynamically linked: `git --version`, `perl -v`, `awk`, `tar`, `make`, and so on. Its output (descriptors 1 and 2) comes back through a capture pipe, it has no input, and it is stopped after 20 seconds. Spawned programs get `PATH`, `HOME` and `TERM` in their environment, and a dynamically linked one starts through its interpreter like under `execve`. Output lines longer than the terminal are wrapped instead of clipped.
- Tab completes the word being typed in the desktop terminal: command names for the first word, directory entries (relative to the working directory, directories get a `/`) for the rest. A unique match is completed with a space after it, several are completed as far as they agree, and when nothing more can be added the candidates are listed. Boot gate `AEROS_SHELL_COMPLETE`.
- The terminal line is editable: Left/Right move the caret (by whole characters), Home/End jump, Delete removes under it, Backspace before it, and typing or pasting inserts at the caret.

### Panic screen
- A kernel panic or an unexpected CPU exception in the kernel now paints the message on the screen (title, location and text on a dark red background, through the virtio-gpu scanout when that is in use) instead of leaving a frozen picture; a machine without a serial port used to show nothing. `--features panic-demo` panics at the end of boot to look at it.

### Boot time
- An ordinary (non-test) boot no longer runs the test suites it used to: the shell command self-test (26 s of the ~55 s), the antivirus self-tests and whole-disk scan, the sign-in/PBKDF2 and desktop render self-tests, and the audit self-test (which also wrote two `SELFTEST` records into the real audit log on every start). ### Frame cost
- The panel drop shadow (`Painter::paint_shadow`) is worked out once per pixel from its distance to the offset panel (the same result as stacking up to sixteen growing copies, which used to be sixteen full-size fills): the dock's settle frame spent ~115 ms in it, now ~7 ms. `fill_rounded_rect`, `stroke_rounded_rect` and the inner shadow skip the per-pixel corner test for the columns no corner square reaches.
- The dock's glass (capsule and clock capsule) is cached separately from its icons, so hover and press animations only repaint the buttons; moving frames reuse a cheap-mode copy that is replaced by the full-quality one at rest.
- Together, in the same QEMU scenario (open Files, Notes, Trash, Settings, launcher, quick settings): median desktop redraw 39 ms -> about 20 ms, frames over 100 ms 8 -> 0 for the shadow change alone and the dock settle spike from ~190 ms to ~60 ms. `AEROS_DESKTOP_REDRAW` now carries `wall_us`, `win_us`, `panel_us`, `dock_us` and `frost_us=[shadow, capture, hblur, vblur+write, edges]` for profiling.
- The Files status line shows the last action ("not a text file", "renamed") instead of being hidden by the selection summary.

### Display
- virgl 3D (`virtio_gpu/virgl.rs`): when the device offers `VIRTIO_GPU_F_VIRGL` the driver creates a 3D context and runs the glass blur on the host GPU: the backdrop rectangle is uploaded to a texture, two draws (horizontal then vertical taps with saturation, brightness and tint, TGSI shaders generated at run time) produce the result, which is read back and written row by row, so a moving panel keeps the real blur instead of the flat tint. Boot logs `AEROS_VIRGL` with a self-test (a known colour through the whole pipeline). With 3D the firmware framebuffer stays the display (QEMU for Windows cannot export a GL texture for scanout). Measured under `egl-headless`: the host round trip costs 2-4 ms per panel, dominated by the read-back, so it improves quality more than speed; panels under 3000 pixels stay on the CPU. Windowed GL (`gtk,gl=on`, `sdl,gl=on`) crashes QEMU on this host even with ANGLE on PATH; `tools/live-gl.ps1` uses `egl-headless` (needs ANGLE's `libEGL.dll`/`libGLESv2.dll` in `build\angle`). The CPU glass is unchanged and remains the path everywhere else.
- virtio-gpu cursor plane: the pointer is a hardware cursor now (`CURSOR_QUEUE`, 64x64 ARGB image, `move_cursor`/`set_cursor_visible`), so moving it never repaints or transfers a frame. Before, a pointer-only move was drawn into the CPU framebuffer but never published to the GPU scanout, so the pointer only updated when something else forced a redraw (seen as a frozen cursor away from the dock). The software cursor remains the fallback when there is no virtio-gpu. Frame publishing sends only the changed rectangle (`FrameBuffer::copy_bgrx8888_changed`, rectangle `TRANSFER_TO_HOST_2D`/`RESOURCE_FLUSH`) instead of the whole surface. Boot-test gate `AEROS_GPU_CURSOR`. The blur and frosting are still CPU-rendered; GPU compositing needs a 3D (virgl) path, which is not implemented.

### Desktop redesign
- Followed the new Figma design: a wider dock (seven rounded-square slots and a time/date capsule), a six-column app launcher with three columns of folders, the new control-centre layout (Wi-Fi pill, Bluetooth, power, screenshot, volume and brightness sliders, airplane mode), the rounded-blob pointer, white setup cards with Back/Next buttons (Back returns to the previous step, Next advances; the final step reads Finish), a green-fading expanded music island, glass context-menu and clipboard panels with white rows, and wider volume/brightness side sliders. ### Union root
- With a home volume mounted `/` is the read-only boot image under a writable layer on the home volume (`/home/.root/upper`): writes copy the file up, new files and directories go to the upper layer, removing an image file records a whiteout, a directory created over a removed one is marked opaque, and listings merge both. Marks persist in `/home/.root/overlay`; `overlay reset` throws the layer away. Directory renames of image directories fail with `EBUSY`. Programs in the upper layer run through the buffered executable path. Boot-test gate `AEROS_OVERLAY` (create, merged listing, copy-up with the image proven untouched, whiteout, re-creation, renames, remount, reset). `docs/OVERLAY.md`.

### Parallel threads
- The threads of one process now run on several processors at once. Changes that remove or downgrade mappings (`munmap`, `mprotect`, copy-on-write breaks, `fork`, `exec`, swap-out) stop the other processors that run the address space first and make them reload it (`scheduler::stop_siblings`); `exit_group` and `execve` end threads that run elsewhere. Found on the way: an interrupt answered by killing the task never sent its EOI, a yielding task kept the kernel lock from a processor queued for it, and a thread killed by `exit_group` overwrote the process's exit status. `userspace/parallel` (`AEROS_SMP_THREADS`) checks real overlap, the fork race, the unmap-and-remap race and exiting with running threads; at four processors the six programs of `AEROS_SMP_PROGRAMS` spread over three processors. `docs/SMP.md`.

### Microcode, performance states, sleep
- `microcode.rs` finds the newest Intel or AMD update for the running processor in a blob (checksums, extended signature tables, the AMD equivalence table; signed Intel revisions) and loads it on every processor (`ucode load <file>`, or `/etc/ucode.bin` at boot). It refuses to touch a virtual processor. Nine host tests in `tools/proto-host` cover the formats; the model-specific register write itself needs real hardware.
- `cpufreq set|max|min` writes a performance state through the register `_PCT` names (I/O port, memory, or the vendor's model-specific register) on every processor. The planning is tested on the host (`tools/aml-host`); the write is untried.
- ACPI S3 (`suspend --yes`, `sleep.rs`, `docs/SLEEP.md`): the other processors are parked, the boot processor's context is saved, the firmware waking vector points at the trampoline the processors start from (now also enabling SSE), and on wake the processor, GDT/IDT/TSS, `syscall` MSRs, FPU, local APIC, IOAPIC table, HPET, clock and ACPI events are restored and the processors restarted. Tested by `tools/s3-quick.ps1` (also the last step of `tools/test.ps1`) on QEMU's emulated CPU: the firmware cannot resume under WHPX. Device drivers have no resume step.

### Kernel
- Per-process ASLR: each process gets a random PML4 slot, inherited on `fork` and kept across `exec`.
- Kernel heap grown from about 2 MiB to 16 MiB using a multi-level page-table mapping.
- Copy-on-write `fork`, demand paging, process groups and sessions, most POSIX signals.
- Shell job control: `cmd &`, `jobs`, `wait`.

### Shell
- New commands: `grep` (`-i`, `-n`, `-c`), `find` (`-name`), `du`, `sort` (`-r`), `uniq` (`-c`), `tee`, `basename`, `dirname`, `seq`, `true`, `false`.
- Pipelines: `a | b | c` (up to four stages). `cat`, `head`, `tail`, `wc`, `grep`, `sort` and `uniq` read the previous stage's output when no file is named; the pipeline's status is the last stage's. Stages run one after another in the kernel, passing one buffer along.

### Threads
- Real threads: `clone` with `CLONE_VM|FS|FILES|SIGHAND|THREAD` (what `pthread_create` passes, with `CLONE_SETTLS`, `CLONE_PARENT_SETTID`, `CLONE_CHILD_SETTID` and `CLONE_CHILD_CLEARTID`) and `clone3` start a new task in the running process. The threads of a process share the address space, descriptor table, directory, signal handlers, limits and seccomp state; each has its own kernel stack, registers, FPU state, thread pointer (FS base, now saved and restored on every switch; a forked child keeps its parent's), signal mask, pending signals and alternate stack. Process state moves on a switch as one unit between processes and only the per-thread part inside one process, the leader's slot holds the shared copy while the process is switched out, and a leader that exits first lingers until its last thread is gone. `gettid` is the task id and `getpid` the process id, `tkill`/`tgkill` address one thread, `exit` ends the calling thread and `exit_group` the process, a fatal signal in one thread ends all, `execve` ends the other threads, and `wait4` reports the process when its last thread is done. `fork` from a thread copies the whole address space; `vfork` and `posix_spawn`'s `CLONE_VM|CLONE_VFORK` get a copy-on-write copy, not a shared one. The address space still has 128 pages for `mmap` (so thread stacks must be small; the standard library's 2 MiB default does not fit), and a process, threads included, holds at most 32 tasks system-wide.
- Futexes (`syscall/futex.rs`) are real wait queues keyed by process and address, with time-outs (relative, absolute, `CLOCK_REALTIME`) and signals ending a wait (EINTR): `WAIT`, `WAKE`, `WAIT_BITSET`, `WAKE_BITSET`, `REQUEUE`, `CMP_REQUEUE`, `WAKE_OP`, and the priority-inheritance calls `LOCK_PI`, `UNLOCK_PI` and `TRYLOCK_PI` (the lock is handed to the oldest waiter on unlock, an owner is boosted to the nice value of the most important waiter until it unlocks, a dead owner's lock is taken over with `OWNER_DIED`). A thread's `set_tid_address` word is cleared and woken as it exits, which is what `pthread_join` waits on, and its robust list is walked: every futex it still held gets `OWNER_DIED` and one waiter is woken. `set_robust_list` and `get_robust_list` work per thread.
- `userspace/threads` (`aeros-threads`) is a Rust `std` program built for musl that the boot-test runs as a real process (`AEROS_THREADS`, exit status 76): joins returning values, four threads doing 80,000 atomic increments, a mutex-protected list, a condition-variable ping-pong of 400 hand-offs, thread-locals, sleeps finishing in time order, channels, a barrier, scoped threads, twenty create-and-join cycles in a row, a file written by one thread and read by another, the process and thread ids, and raw `futex` checks of requeue, wake-op, priority-inheritance hand-over (including the lock bits and the `EDEADLK` an owner gets from a try-lock) and the robust list of a thread that exits holding a lock. Each step prints `AEROS_THREADS_STEP name ok`.

### Debugging
- `ptrace` (`syscall/ptrace.rs`): `TRACEME`, `ATTACH` (the parent, or a task holding the new `CAP_SYS_PTRACE`), `DETACH`, `CONT`, `SYSCALL`, `SINGLESTEP`, `KILL`, `PEEKTEXT`/`PEEKDATA`/`PEEKUSER`, `POKETEXT`/`POKEDATA`/`POKEUSER`, `GETREGS`/`SETREGS` (`user_regs_struct` order), `GETFPREGS`/`SETFPREGS` (the 512-byte FXSAVE image), `GETSIGINFO`, `GETEVENTMSG` and `SETOPTIONS` (`TRACESYSGOOD`, `TRACEEXEC`, `EXITKILL`). A traced task stops in its own context for a signal about to be delivered (the tracer can suppress or replace it), system call entry and exit (a negative `orig_rax` left at entry skips the call), a successful `execve`, `int3`, single-step traps and user faults (SIGSEGV/SIGFPE/SIGILL/SIGBUS); `wait4` reports the stops as `(signal << 8) | 0x7f`. Pokes into shared or copy-on-write pages (program text after a `fork`) give the tracee a private copy first. Signals sent to a traced task are always queued so the tracer sees them. Not done: threads as tracees, `SEIZE`/`INTERRUPT`, `TRACEFORK`/`TRACECLONE`/`TRACEEXIT`, debug registers, `PTRACE_GETREGSET`; a signal-delivery stop inside a system call comes after the syscall-exit stop, and a SIGSTOP given by the tracer is dropped instead of stopping the task.
- `wait4(-1)` now looks at every child (it used to follow only the first one) and at tasks the caller traces. A freed task slot no longer hands its old exit status to the next task that takes it (a second child in the same slot used to be reported as already finished).
- `userspace/ptrace` (`aeros-ptrace`) is the boot-test's tracer (`AEROS_PTRACE`, exit status 77): signal stop and suppression, entry/exit stops with a changed return value, skipped calls, `int3` stops, register and memory edits (data and code, with the parent proven untouched), single steps, FPU edits through `SETFPREGS`, the `execve` event, a traced null write, `PTRACE_KILL`, and `ATTACH`/`DETACH` on a running task. Each step prints `AEROS_PTRACE_STEP name ok`.

### Benchmarks
- `userspace/bench` runs the same static micro-benchmarks on AerOS (boot-test gate `AEROS_BENCH`) and on Linux (`tools/bench-linux.ps1`, a Debian-kernel initramfs in the same QEMU configuration). `docs/BENCHMARKS.md` has the first comparison: CPU and memory work is within 2-3x of Linux, but every system call is about 250x slower (37 µs for `getpid`), which makes file and pipe operations the same factor slower. Unprofiled; that is the next performance task.

### AerFS
- `aerfs.rs` is a copy-on-write filesystem: nothing is overwritten in place, every block pointer carries the CRC-32 of its target, and every change is one transaction committed by a single atomic superblock-sector write (two alternating slots), so a power cut leaves either the old tree or the new one and there is nothing to replay or repair. Files, directories and the inode table are 512-way radix trees; free space is rebuilt at mount from the metadata. `volume.rs` gives the VFS one interface over FAT and AerFS (an AerFS file is presented as a `fatfs::Node`), `datafs` mounts AerFS volumes under `/media` (USB sticks and SD cards that carry one mount by themselves), the shell gains `aerfs format|mount <disk>`, `fsck` works on them, and `/proc/mounts` shows the type. Limits: 256 MiB per volume, 58-byte names, no links, two volumes at once. `docs/AERFS.md` has the design and its limits.
- Tested by `tools/aerfs-host` (the same source against a RAM device that loses power mid-block: a 17-step script is cut at every sector write and the recovered filesystem must mount, pass `fsck` and equal the state before or after the step; 4,000 random operations against a model, a bit flipped in every block of a volume, running out of space, allocation-map agreement after remount) and by the boot-test gates `AEROS_AERFS_CRASH` and `AEROS_AERFS_VFS` (the cut-at-every-sector test inside the kernel through the volume layer, and the whole path through `/media` with a remount). It found one real flaw on the way: directories did not give back their space after entries were removed.
- Not done: AerFS as the home volume, an overlay that makes `/` itself writable, hard and symbolic links, encryption.

### Performance
- Profiling the benchmark (`kernel/src/perf.rs`, `AEROS_PERF` lines) found the reason system calls were 250 times slower than Linux and fixed three unrelated causes: the monotonic clock read the HPET over memory-mapped I/O on every call (it is now the calibrated time stamp counter, checked against the HPET and refined every ten seconds; `time.rs`, gate `AEROS_CLOCK`); the antivirus scan on every file open and close compared every signature needle at every byte (needles are now indexed by first byte, 1.7 ms to 40 µs for 4 KiB; `antivirus.rs`); and the idle boot task was handed the CPU whenever a process blocked and slept a whole timer tick (a blocked read, wait or exit now yields work-first; `scheduler.rs`). `getpid` 37,066 ns to 344 ns, pipe round trip 1.43 ms to 6 us, `fork` plus `wait4` 1.44 ms to 32 us, tmpfs create-write-read-unlink 6.4 ms to 0.25 ms. `docs/BENCHMARKS.md` has the table and the reasoning.

### Kernel image randomisation
- At the very start of boot (`uefi::relocate`, called first thing in `kernel_entry`, before the image data has been used) the kernel finds its own PE headers, picks a random 2 MiB-aligned free region from the firmware memory map with `aslr::pick_slot`, allocates it as loader code at that exact address, copies the headers and each section's data, applies its own base relocations for the new address (`aslr::apply_relocations`, 4,944 of them) and jumps to its entry point in the copy. The copy hands the original's pages back to the firmware. `AEROS_KASLR` reports where it moved from and to, how many slots there were, and checks that a pointer stored in the image points into the copy.
- Tested by `tools/aslr-host` (PE parsing, relocation of a synthetic image, malformed tables refused, uniform slot choice, and the real `BOOTX64.EFI` laid out as firmware does and moved twice with every relocated pointer checked to lie inside the image), by the whole boot-test running from a relocated image, and by `tools\kaslr-check.ps1`, which boots it several times and checks the base address varies.
- What it hides is the image: physical memory is still mapped at its own addresses on the kernel's identity map, so this is not a full KASLR (no higher-half kernel, no randomised direct map). It needs about 71 MiB of free memory at boot on top of the image the firmware already loaded; with less it stays where it was loaded (reported as `relocated=false`).

### Intel VT-x
- `vmx.rs` is a VT-x backend that runs the same smoke guests as the AMD-V path (a real-mode and a 64-bit program, plus the Linux boot-protocol probe) on VMX with EPT: `IA32_FEATURE_CONTROL`, CR0/CR4 fixed bits, `VMXON`, a VMCS per guest, an assembly VM-entry/exit path, and handling for CPUID, HLT, I/O, MSR, external-interrupt and EPT-violation exits. `svm.rs` now exports the guest programs and the Linux image loader so both backends use the same ones.
- **Not run on an Intel processor.** This machine is AMD and QEMU cannot offer VMX to a guest here. The pure parts (`vmx_logic.rs`: VMCS field encodings, control adjustment, access-rights conversion, the EPT tables, exit decoding) are tested on the host by `tools/vmx-host`, including a check that every field encoding matches the SDM layout and a software EPT walk of every mapped page; the rest is covered only by the compiler. The boot-test gate `AEROS_VMX` reports a skip here and requires all three guests to pass where VMX exists. The self-test is compiled into boot-test builds only, so an ordinary boot is unaffected. `docs/VTX.md` says how to run it and how to read a failure.
- Not done: the Linux desktop window and the guest devices are still AMD-V only (the ~3,200 lines in `svm.rs` that read VMCB fields need a backend interface), VPID, MSR and I/O bitmaps, NMI exiting.

### TLS 1.3
- `kernel/src/tls/` is a TLS 1.3 client written from scratch in `core`-only Rust (no heap): X25519 key exchange on the Ed25519 field arithmetic, ChaCha20-Poly1305 and AES-128-GCM records, the RFC 8446 key schedule (HMAC and HKDF over SHA-256), key updates, and `close_notify`. Server certificates are checked for real: an X.509 parser, RSA (PKCS#1 v1.5 and PSS, 2048 to 4096 bits) and ECDSA (P-256, P-384) and Ed25519 signatures, hostname matching (SANs, wildcards, IPv4 literals), validity dates against the RTC, CA and path-length constraints, key usage, and a built-in table of 136 trust anchors taken from the Mozilla list (`tools/make-tls-roots.py`). Only the SHA-256 suites are offered; HelloRetryRequest, client certificates, resumption and 0-RTT are not supported, and neither are name constraints (a certificate that has them is refused) or revocation checking (no CRL, OCSP or stapling).
- `tlsnet.rs` runs the client over the TCP engine (`https_get`, one session at a time in static memory) and the `https <host> [path]` shell command (COMMANDS=84) fetches a page and reports the certificate result.
- Testing is layered. `tools/tls-host` compiles the same source on the host and checks it against published vectors (RFC 7748, 8439, 5869, 8448, NIST GCM), against signatures and certificate chains made by OpenSSL (RSA, ECDSA, Ed25519, mixed chains, a non-CA intermediate, wrong names, expired and untrusted roots), against live `openssl s_server` handshakes with both suites, and against corrupted and truncated server bytes (every flipped or cut position in the handshake must fail). Key updates, replay and tampering are unit tests on two sessions. The boot-test adds `AEROS_TLS_KAT` (the vectors and four OpenSSL signatures inside the kernel) and `AEROS_TLS_NET` (the guest handshakes with two `openssl s_server` processes the harness starts on a throwaway CA, one RSA with ChaCha20-Poly1305 and one ECDSA with AES-128-GCM, and must refuse a wrong name and an unknown root). The test CA is made per run by `tools/make-tls-test-pki.py`; no private keys are committed. The boot-test also prints `AEROS_TLS_INTERNET` lines (informational, it needs the internet): the guest fetches `/` over TLS 1.3 from example.com, www.google.com, github.com, www.wikipedia.org, aws.amazon.com and www.microsoft.com with the built-in roots; all six verified and answered 200 on 2026-10-07.
- Not done: the AES S-box is a table lookup (not constant-time against cache attacks; ChaCha20-Poly1305 is preferred and listed first), TLS 1.2, session resumption, ALPN, and using TLS in the desktop browser and the package manager.

### Signed updates and measured boot
- `update <image> <signature>` (`update.rs`, administrator-only) installs a new boot image only if its Ed25519 signature verifies against a key trusted with `pkg trust`. The image is mounted-volume work done by the crash-tested FAT driver on the boot volume: written to `EFI/BOOT/BOOTX64.NEW`, read back and hashed, the running image copied to `BOOTX64.OLD`, then one crash-safe rename puts the new one in place. `update rollback` puts the old one back. Both are audit-logged and seal the new digest for the measured-boot check. A power cut at any sector write leaves either the old or the new image whole: the boot-test cuts power after every write count of a whole update on a RAM-disk FAT volume (`AEROS_UPDATE`, 55 cases, none torn) and also checks a wrong-key signature, a tampered image and an empty key store are refused without touching the volume.
- Measured boot (`measure.rs`): at start-up the boot image on the FAT volume and the built-in program archive are hashed and folded into a running SHA-256 register the way a TPM extends a PCR; `measure` prints the log, the register and whether the image matches the digest sealed by `update` or `measure seal` (`/data/MEASURE.REF`); a mismatch is written to the audit log as an alert. Gates `AEROS_MEASURE` and `AEROS_MEASURE_TEST`.
- Not done: UEFI Secure Boot signing (the firmware's keys are outside the project), a TPM driver (the register is in software, so it does not protect against someone who can alter the kernel and the sealed file together), updating anything but the boot image, refusing to boot a changed image.

### Swap and stack protection
- Swap (`swap.rs`, with `process_swap_out/in` in `arch/paging.rs`): a partition formatted as swap (GPT type "Linux swap" or MBR type 0x82, and the `SWAPSPACE2` signature in its first page) on the boot disk becomes a pool of up to 16,384 4 KiB slots, read and written straight through the disk driver. Heap, anonymous-mapping and grown-stack pages of processes that are not running are evicted when memory is critical (`oom::relieve` tries it before killing anything); pages still shared with a forked relative stay in memory. An evicted page's page-table entry is "not present, swapped" with its slot, and touching it (a user fault, a kernel copy to or from user memory, `ptrace`) reads it back. `fork`, `mprotect` and file-backed `mmap` bring a process's pages back first; `munmap`, `exec` and exit free the slots. `/proc/meminfo` shows SwapTotal and SwapFree and the `swap` shell command shows use (COMMANDS=81).
- Boot-test (`AEROS_SWAP`): a 6 MiB swap area on the virtio test disk, a std program that keeps heap and mmap regions filled with a versioned pattern, rewrites and checks pages for 0.6 s while the kernel evicts eight pages on every tick: ~700 pages written, ~600 read back, no mismatch, all slots free after the program exits.
- Stack protector: the kernel is built with `-Zstack-protector=strong` (`.cargo/config.toml`; the flag is unstable, so `RUSTC_BOOTSTRAP=1` is set there too). `stackguard.rs` supplies the MSVC-style `__security_cookie` (redrawn from RDRAND and the TSC first thing in `kernel_entry`, low byte clear) and `__security_check_cookie`, which prints `AEROS_STACK_SMASH` and halts. Boot-test (`AEROS_STACK_PROTECTOR`): the cookie differs from its default, a function with a buffer loads it, the image holds hundreds of check calls, the check accepts the right value and rejects a wrong one.
- Not done: encrypted swap.

### DMA protection
- AMD-Vi IOMMU driver (`iommu.rs`): the IVRS table gives the unit's registers, the address ranges firmware wants mapped one-to-one and the interrupt-forwarding flags of special devices. Every PCI function found at boot (plus the alias and special devices IVRS names) gets a device table entry in one shared domain with a 4-level page table; every other device id is pointed at an empty table and is blocked. The domain maps only memory drivers set aside for DMA (`FrameAllocator::allocate_dma`, used by the AHCI, NVMe, xHCI, virtio, e1000, RTL8139/8168, HDA and AC'97 drivers) and, for the length of one command, the buffer a caller hands to AHCI (`iommu::window`, reference-counted per page). Interrupts pass through unmapped. Commands (`INVALIDATE_DEVTAB_ENTRY`, `INVALIDATE_IOMMU_PAGES`, `COMPLETION_WAIT`) and the event log are real; a fault shows up in `/proc/iommu` (state, mapped pages, fault count, last fault).
- The tables are built before the drivers start; `enable` runs once they are up and keeps the unit on only if the boot disk reads back the same first sector through it, so a mistake costs the protection and not the boot.
- Boot-test (`AEROS_IOMMU`): QEMU's `amd-iommu,dma-remap=on` plus the `edu` test device, whose DMA engine is pointed at a page: it reads and writes the page at a mapped address that is not the page's physical one, its writes and reads at the page's unmapped physical address are blocked and logged, and a withdrawn mapping closes the page again (which also proves the invalidation). Every driver's DMA in the rest of the boot-test runs through the unit.
- Not done: Intel VT-d, interrupt remapping, a domain per device, ATS/PRI, large pages in the I/O page table. Only QEMU has run this; on real hardware the unity ranges, device-entry flags and alias entries are parsed from the IVRS but untested.

### ACPI
- AML interpreter (`aml.rs`, no kernel dependencies, fixed-size tables, no allocation): definition blocks (DSDT and every SSDT) are executed into a namespace of up to 12,288 objects (scopes, devices, processors, thermal zones, power resources, names, methods, operation regions, fields, index and bank fields, buffer fields, mutexes, events, aliases). Methods are interpreted from the bytecode: control flow, integer/string/buffer/package operations, references (`Index`, `DerefOf`, `RefOf`, `CondRefOf`), conversions, `Match`, `Concatenate`, `Mid`, `Stall`/`Sleep`, `Notify` (counted), predefined `\_OSI`, `\_OS_`, `\_REV`, `\_GL_`. Integers are 32-bit for a revision-1 DSDT and 64-bit otherwise. Package elements that name objects defined later are resolved when used. Operation regions: SystemMemory (only mapped addresses), SystemIO, PCI_Config (functions directly under a root bridge); EmbeddedControl and the rest report `Unsupported`.
- `acpi_ns.rs` loads the tables at boot, calls `_PIC(1)`, and serves `\_S5_` to the power-off path (the old byte scan stays as a cross-check), resource-template decoding and the new `acpi` shell command (`acpi`, `acpi tree`, `acpi eval <path> [args]`, `acpi crs <path>`). `pci::config_read/config_write` and `paging::kernel_range_mapped` back the hardware accesses.
- Tests: `tools/aml-host` runs the interpreter on a host against a DSDT captured from QEMU (`cargo test` in that directory: namespace, `_S5_`, PCI root `_HID`/`_CRS`, `_PRT` in PIC and APIC mode, every `_STA`/`_CRS`/`_HID`/`_ADR`); the boot-test gates `AEROS_AML` and `AEROS_AML_QUERIES` (S5 equals the byte scan, PCI0 `_CRS` holds port 0xCF8, COM1 `_CRS` is I/O 0x3F8 plus IRQ 4, all 128 `_PRT` sources are devices, LNKA `_CRS` read through PCI config space).
- Not done: GPE/SCI handling (so no hot-plug or button events), `_INI`/`_REG` calls, sleep states beyond S5, battery, thermal and CPU frequency control, EC regions, `Load`/`LoadTable`, nested PCI buses in `PCI_Config` regions.

- Priorities: each task has a nice value (-20..19, inherited on `fork`); the scheduler prefers lower values but ages passed-over tasks so none starves. Set with `renice` (privileged) or `setpriority`, read with `getpriority`; `ps` shows an NI column. Equal nice values behave like the previous round-robin.

- SMP job scheduler (`smpsched.rs`): every application processor has its own run queue; a job carries a nice value and an affinity mask, goes to the least loaded CPU its mask allows, runs in priority order with aging, and an idle processor takes the best job it is allowed to run from the busiest queue. `bench smp` hashes on every processor at once, `/proc/schedstat` shows jobs per CPU and steals. User tasks still run only on the bootstrap processor (the Linux process state is global), so this is not a preemptive multi-CPU task scheduler. `AEROS_SMP_SCHED` checks placement, stealing, priority order, affinity, refusal of an impossible mask and, with `-CpuCount 4`, balancing and stealing across three processors.

### Package manager
- `pkg` (privileged): `install <file> [signature]`, `list`, `remove`, `rollback`, `verify`, `path <name>` and `trust <key-hex>`. A package is a text header (name, version, up to 16 files with path, mode, size and SHA-256) followed by the files' bytes; the 64-byte Ed25519 signature next to it covers the whole file and has to verify against a key added with `pkg trust`. Nothing is read from a package before its signature checks out, every file is hashed as it is written and compared with the header, paths may not be absolute or contain `.` or `..`, and a failed install removes whatever it wrote. Files go to `/home/pkg/apps/<name>/<version>/`; the previous version stays installed so `rollback` only changes a pointer, and a third version removes the oldest. `verify` re-hashes the installed files against the recorded manifest. The boot-test (`AEROS_PKG`) runs install, update, rollback, forward again, rotation, an untrusted key, a one-byte change, a short signature, a wrong declared hash, a path escape, a truncated body and tampering with an installed file, using packages signed offline (`tools/make-pkg-vectors.py`). Removing the signature check and the hash check together makes it fail. `tools/aeros-pkg.py` builds and signs packages on the host (`keygen`, `pubkey`, `build`, `sign`; needs Python and OpenSSL). There are no dependencies between packages.

### Security
- Ed25519 signature verification and SHA-512 (`ed25519.rs`), checked against signatures generated with OpenSSL, including tampered, non-canonical and wrong-key cases. `sigcheck <file> <signature-file> <public-key-hex>` verifies a signed file. No update key is built in yet and no secure-boot chain uses this; it is the primitive for signed updates.

- Capabilities: each process has effective and permitted capability sets, full by default, inherited on `fork`, kept across `exec` and only ever shrinkable (`capset` can drop but never regain). `capget`/`capset` report and change the real sets. Enforced for raising a process's priority (`CAP_SYS_NICE`), signalling another process (`CAP_KILL`), `chown`/`fchown`/`fchownat` (`CAP_CHOWN`), binding a port below 1024 (`CAP_NET_BIND_SERVICE`, EACCES), setting the clock with `clock_settime` and `settimeofday` (`CAP_SYS_TIME`), `reboot` (`CAP_SYS_BOOT`) and `mount`/`umount2` (`CAP_SYS_ADMIN`); a user process that drops them gets EPERM (EACCES for the port). `AEROS_CAPABILITY` drops each in turn and checks the refusal and that the call works again afterwards. Everything else root can do is not gated. `clock_gettime` now also answers `CLOCK_REALTIME` and the coarse, raw and CPU-time clocks (the last two report elapsed time), and `reboot` validates the Linux magic numbers.
- Seccomp filter mode: `seccomp(SECCOMP_SET_MODE_FILTER)` takes a classic-BPF program that is validated, then run on every syscall (allow, fail with an errno, or kill). One filter per process, inherited across `fork` and `exec`; stacking filters is not supported.

### Benchmarks
- `bench` shell command: memcpy, SHA-256 and random-fill throughput plus file lookup, tmpfs write and `yield` rates, each measured over a fixed time slice.

### Memory
- Slab allocator (`slab.rs`): seven size classes from 16 to 1024 bytes carved from 4 KiB heap pages, each page with a header, free list and use count; an empty page goes back to the heap (one spare per class is kept, `reclaim` returns the spares under pressure), freed objects are zeroed, and a double free, a wrong-size free or a pointer that is not a live object is refused. Layouts above 1 KiB or 64-byte alignment fall through to the heap. The scheduler's per-task FPU areas (832 bytes, 64-byte aligned) come from it; `/proc/slabinfo` shows the classes. `AEROS_SLAB` allocates 400 mixed objects, checks alignment and contents, frees in a shuffled order and requires the heap's free bytes and allocation count to come back exactly.
- Memory-pressure levels (low at 10% free, critical at 3%) shown by `free`. When `fork` or `mmap` fails under critical pressure, the other user task holding the most pages is terminated (`AEROS_OOM_KILL`). `ps` now shows a PAGES column with each process's resident pages.

### Storage
- Block layer (`block.rs`) between the filesystems and every disk driver: one `Disk` type for AHCI, NVMe, USB, SD and virtio-blk, per-disk counters (`/proc/diskstats`), a write-through page cache of up to 256 4 KiB pages that fills on read, reads ahead of a sequential reader, and gives its pages back under memory pressure (`oom::relieve` empties it before it kills a process; `/proc/vmstat` and the Cached line of `/proc/meminfo` show it). A failed write drops the cached copy. `block::submit` is an I/O scheduler for batches: requests are issued in one upward sweep from the head position (C-LOOK), neighbouring requests of one kind are merged into runs of up to eight sectors, a barrier ends a group, and a group in which a write overlaps another request keeps its submission order. FAT file reads gather the clusters they need and submit them as one batch. The boot-test (`AEROS_BLOCK`) shows 48,233 sectors of head travel for a random batch in submission order against 7,106 scheduled, 48 commands against 7 for a contiguous one, barrier and overlap ordering, cache hits, write-through, a power-cut write, LRU eviction, read-ahead and a full reclaim that returns every page; reverting the sort makes it fail.
- Mount table (`mounts.rs`): `/`, `/tmp`, `/proc`, `/sys`, `/home`, `/media/<label>` and bind mounts are listed by `mount` and `/proc/mounts`. `mount --bind <directory on /home or /media> <directory in the root tree>` (privileged) and `umount <target>` change the table, as do the Linux `mount(MS_BIND)` and `umount2` calls (they need the new `CAP_SYS_ADMIN`); a bound directory cannot be removed or renamed, and paths are rewritten to the volume before any VFS call, so every file operation works on it. At boot `/var`, `/opt`, `/srv` and `/root` are bound to `/home/.root/...`, which makes those directories of the root tree writable and persistent (`AEROS_MOUNTS` writes through `/var`, renames, lists, remounts the volume and reads the file back; removing the mount-point protection makes it fail). The rest of the root tree is still read-only and `/etc` is not persistent.

- Installer (`installer.rs`) on disks that already hold data: a disk whose only content is a valid GPT can take the system in its largest free gap of at least 288 MiB (`MIN_PARTITION_SECTORS`), and nothing is written until the new partition is formatted and filled; only then is the entry added, backup table first and primary last (a power cut at every one of the 66 writes leaves at least one complete valid table), and afterwards every earlier entry is compared byte for byte. A disk with a damaged table (bad header or array checksum, a different backup, overlapping or out-of-range entries), a table with no free slot or no big enough gap, an MBR-only disk, or raw data is refused with the reason (`refusal=` in `AEROS_INSTALL`). A blank disk still gets the whole disk, as before. Existing disks need permission: `install <disk> --yes` in the shell (privileged; `install` alone lists the disks and what would happen, the boot disk is never a target), or an `INSTALL.CFG` containing `free-space` on the boot disk for an unattended install. `AEROS_INSTALLER` checks the planning, the refusals and the power-cut property on a RAM disk (replacing the table checks or the write order makes it fail), and `tools/test-install-existing.ps1` does the whole thing in QEMU: a 640 MiB disk with a 96 MiB partition is left byte-identical when no permission is given, with permission the new partition goes after it (`tools/make-gpt-disk.py` checks both tables, the old partition's SHA-256 and the FAT32 volume) and the machine boots from the result.

### Services

### Services
- `svc` shell command (privileged): `add`, `start`, `stop`, `restart`, `rm` and `list` for named background programs.

- `fsck [--repair] [mount-point]` (privileged) checks a `/home` or `/media` filesystem using the raw FAT: broken chains, clusters shared by two entries, sizes larger than their chain, and clusters no entry owns. With `--repair` it cuts broken chains at their last good cluster, lowers oversize files to fit, and frees leaked clusters; shared clusters are only reported. The power-loss test runs a repair pass after every simulated cut and requires a clean second pass (426 leaked clusters repaired across 189 cases). The home volume is checked when it is mounted (`AEROS_HOME_FSCK`) and repaired automatically if it is damaged; leaked clusters alone are left for a manual `fsck --repair`, and volumes over about a million clusters are skipped.

- Hostile-disk hardening for the `/home` and `/media` filesystem: a directory whose cluster chain loops (or never ends) used to make listing run forever, and `extend_dir` had an unbounded loop on the same input. Directories are now capped at the format's 65,536 entries, `extend_dir` reports corruption after a bounded walk, and directory reads keep a chain cursor instead of re-walking the chain for every entry. A directed test builds exactly that looping directory; with the cap removed the boot hangs, with it the test passes. Boot fuzzing now also covers random seccomp BPF programs, the shell parser, pipeline splitter and path normalizer, VFS path lookups, Ed25519 on garbage input, 150 randomly corrupted FAT images for each FAT implementation, mutated package headers, random `/proc` paths (which must never map outside the hidden directory) and generated TCP frames with fixed-up checksums (184k inputs in about 5 seconds).

### Tracing
- The last 64 Linux syscalls (task, number, first argument, time) are kept in a ring and listed by the privileged `strace [lines]` command, with names for about 50 common syscalls.

### Crash reporting
- The last 8 user processes killed by a CPU fault are recorded (pid, vector, error code, fault address, instruction pointer, uptime) and listed by the privileged `crashes` command. `crashes save [path]` writes a report (the records plus the last 40 kernel-log lines, mode 0600) to `/home/crash-report.txt` or the given path, so it survives a reboot when saved under `/home`.

### Logging
- 16 KiB kernel log ring fed by all serial output, with a privileged `dmesg [lines]` command.

### Filesystem
- `/proc` (read-only): `version`, `uptime`, `meminfo`, `cpuinfo`, `loadavg`, `stat` (CPU time counters are zero; `btime`, process count and CPU lines are real), `mounts`, `filesystems`, `sys/kernel/{ostype,osrelease,hostname,pid_max}`, `sys/vm/{overcommit_memory,swappiness}`, and `self/` (or the process's own id) with `status` (pid, parent, resident memory, effective and permitted capabilities, seccomp mode), `stat`, `statm`, `comm`, `maps` (the process's regions in Linux's format: image pages grouped by permission, `[heap]`, anonymous mappings, `[stack]` including grown pages) and empty `cmdline` and `environ`. It is not a mount: the VFS rewrites `/proc/...` to a hidden directory under `/tmp` and regenerates the files it names just before opening, statting or listing them, so every tool that already reads files can read it, and two readers of one file at the same moment share a copy. Other processes' directories, `/proc/self/fd` and `/proc/self/exe` as a file (readlink still answers) are not provided; writes and creates under `/proc` get EACCES. A small `/sys` works the same way: `devices/system/cpu/{online,possible,present,kernel_max}` and `kernel/mm/transparent_hugepage/enabled`. The tmpfs grew to 96 nodes and 56 file slots to hold both.
- Symlinks on tmpfs (`ln -s`, `readlink`, leaf-only following with a hop limit).
- `~/.aershrc`-style startup script run at login (`/home/.aershrc`).

### Linux compatibility
- `sendmsg` and `recvmsg` on stream sockets (TCP and AF_UNIX: every vector, `recvmsg` waits only for the first byte) and on UDP sockets (one vector, with the peer address); ancillary data is refused with EOPNOTSUPP and the output length fields are cleared. Not exercised by the boot-test beyond the shared vector helper, since the syscalls take user pointers.
- New syscalls: `lstat`, `symlink`, `symlinkat`, `creat`, `getrlimit`, `getpgrp`, `getgroups`, `getresuid`, `getresgid`, `truncate`, `ppoll`, `getrusage`, `times`, `sched_getparam`, `sched_getscheduler`, `prctl` (name, dumpable, no-new-privs only).
- `readlink` and `readlinkat` now return real symlink targets.
- `epoll`, AF_UNIX sockets, seccomp strict mode.

- Runtime-probe syscalls: `capget`/`capset` (see Security), `getpriority`/`setpriority`, `sched_get_priority_max`/`min`, `sched_setaffinity` (validated, not enforced).
- More syscalls: `faccessat`, `epoll_create`, `epoll_pwait` (signal mask ignored), `utimensat` (checks the path, records no time), `fadvise64`, `mlock`/`munlock`/`mlockall`/`munlockall`, `setuid`/`setgid`/`setgroups` (only root values accepted), `chroot` (always refused).
- `eventfd` and `eventfd2` (counter, `EFD_SEMAPHORE`, `EFD_CLOEXEC`; `EFD_NONBLOCK` is accepted but reads and writes always retry briefly and then return EAGAIN, as pipes do). Works with `poll`, `select` and `epoll`; shares `pipe`'s slots (eight in all). Mutation check: ignoring semaphore mode fails the boot-test. `timerfd_create`, `timerfd_settime` (relative or `TFD_TIMER_ABSTIME`, one-shot or periodic, returns the previous setting) and `timerfd_gettime`: the descriptor reports readable once the timer has expired, a read returns the number of expiries since the last read and waits for the next one if the timer is armed (EAGAIN if it is not), and all three clock IDs use the monotonic clock. Dropping the periodic catch-up count fails the boot-test. `signalfd` is not implemented.
- More syscalls: `flock` (validated, locks are not enforced), `sync`, `syncfs`, `close_range` (including `CLOSE_RANGE_CLOEXEC`), `preadv`, `pwritev`, `fallocate` (mode 0 grows the file, `KEEP_SIZE` is accepted), `fchdir`, `personality` (only `PER_LINUX`), `sched_setscheduler` (default policies only; real-time policies get EPERM), `mincore` (reports every page resident) and `membarrier` (query only). `memfd_create` makes a hidden `/tmp/.memfd-N` file that is deleted when its last descriptor closes or its process exits (the name argument is only checked, and sealing is not supported). `sendfile` (file to a file, pipe or unix socket, with or without an offset) and `copy_file_range` (file to file, with or without offsets; no reflinks, flags must be 0) copy in 256-byte steps, up to 64 KiB per call. Not done: `splice`, `mremap`, `link`/`linkat`, `recvmsg`/`sendmsg`, `inotify`.

- `select` and `pselect6` (readiness shared with `poll`; no exception conditions, signal mask ignored).
- Socket API: `setsockopt` (accepted, not acted on), `getsockopt` (`SO_TYPE`, `SO_ERROR`, `SO_ACCEPTCONN`), `getsockname`, `getpeername`, `shutdown`.

### Networking
- IPv6 (`ipv6.rs`, `ip.rs`): one 16-byte address type for both versions (IPv4 is the IPv4-mapped form). At boot the machine solicits a router advertisement, takes the first `/64` prefix with the autonomous flag (global address from the EUI-64 identifier), the router's link-layer address and any DNS server from it, resolves the router with a neighbor solicitation and announces its global address. While the stack runs (`tcpnet::poll`) it answers neighbor solicitations and echo requests for its own addresses (neighbor discovery messages need hop limit 255), learns neighbours into an eight-entry cache, and frames and parses TCP and UDP over IPv6 with their pseudo-header checksums; TCP over IPv6 uses a 1440-byte MSS. `socket(AF_INET6)` works for streams and datagrams with `sockaddr_in6` (28 bytes) in `bind`, `connect`, `accept`, `sendto`, `recvfrom`, `getsockname` and `getpeername`; an `AF_INET6` socket is dual-stack (an IPv4 peer shows as `::ffff:a.b.c.d`), an `AF_INET` listener refuses IPv6 peers, and the unspecified address as a destination means this machine, as on Linux. `::1` stays in the kernel. `IPV6_V6ONLY` is stored and turns the dual-stack off for a listener. Shell: `ping <ipv6>`, `dns -6 <name>` (an AAAA query through the DHCP-supplied DNS server), `ip`, `route` and `arp` show the IPv6 address, router, DNS server and neighbours, and `netstat` lists the real sockets and bound UDP ports. The boot-test checks neighbour solicitation and echo answers (and that a solicitation with hop limit 64 or for someone else's address is ignored), a corrupted echo and TCP segment, address text round trips, `AF_INET6` TCP and UDP over `::1` with the dual-stack and refusal cases, and then, through the card, an HTTP download from the host over IPv6 (`AEROS_HTTP6`, the host serves on `::1` and the guest reaches it as `fec0::2`) and an AAAA lookup for `localhost` (`AEROS_DNS6`). Not done: duplicate address detection, address lifetimes and re-advertisements, DNS transport over IPv6, extension headers and fragmentation, IPv6 in the browser.
- TCP selective acknowledgement: SACK-permitted is offered on every SYN and used when both ends send it. A receiver keeps segments that arrive beyond the next expected byte (up to four ranges, merged when they touch, most recent first) and reports them as SACK blocks on its duplicate acknowledgements; a sender keeps a scoreboard of what the peer has, and after three duplicate acknowledgements resends only the holes (two segments per acknowledgement), sending new data meanwhile by counting only the bytes not yet received. Without SACK it still goes back to the first unacknowledged byte. The receiver's buffering also helps peers that send no SACK. `AEROS_TCP_ENGINE` checks the block layout exactly (a single block, two adjacent segments merged, a second block listed first, the cumulative acknowledgement jumping over everything contiguous once the gap fills, the stream intact) and, for a burst of three lost segments, that the SACK sender finishes without a timeout and puts at least ten fewer data segments on the wire than a sender without SACK (the real-card runs of the same engine pass too).
- Socket options (`sockopt.rs`): `setsockopt` stores and `getsockopt` returns `SO_REUSEADDR`, `SO_REUSEPORT`, `SO_KEEPALIVE`, `SO_BROADCAST`, `SO_LINGER`, `SO_RCVTIMEO`, `SO_SNDTIMEO`, `SO_SNDBUF` and `SO_RCVBUF` (doubled and clamped like Linux), `SO_DOMAIN`, `SO_PROTOCOL`, `IP_TTL`, `IP_TOS`, `TCP_NODELAY`, `TCP_CORK`, `TCP_QUICKACK`, `TCP_KEEPIDLE`/`KEEPINTVL`/`KEEPCNT` and `IPV6_V6ONLY`, with Linux's errors (EINVAL for a short value, EDOM for a bad `timeval`, ENOPROTOOPT for an unknown option). Acted on: `SO_REUSEADDR` (a restarted server can bind while connections from its previous run linger in `TIME_WAIT`; only a listener blocks it), receive and send time-outs on blocking stream and datagram sockets (EAGAIN when they pass), `SO_LINGER` with a zero time (closing sends a reset), `IPV6_V6ONLY`. Stored and reported only: keep-alive probing, `TCP_NODELAY` (there is no Nagle delay to turn off), the TTL and TOS actually put on packets, buffer sizes (the windows stay 8 KiB). `recv` handles `MSG_PEEK`, `MSG_WAITALL`, `MSG_DONTWAIT` and, for datagrams, `MSG_TRUNC` (the real length is returned when the datagram was cut); `FIONREAD` and `FIONBIO` work on sockets. A bug found on the way: closing a listening socket also destroyed the connections it had already accepted; they now live on. `AEROS_SOCKOPT` covers all of it.
- The e1000 now accepts multicast frames. It had been dropping them, which is why no IPv6 router advertisement ever arrived and the old IPv6 check had to be lenient; the harness now requires the whole IPv6 exchange.
- UDP rebuilt around a port table (`udp.rs`): every bound port owns a queue of four datagrams, filled by one shared receive path, so a datagram that arrives while its owner is busy is kept instead of dropped. Sockets can now `bind` (port 0 or taken ports behave as on Linux: EADDRINUSE), receive from any peer unless connected, block in `recvfrom` (EAGAIN with `O_NONBLOCK`/`SOCK_NONBLOCK`/`MSG_DONTWAIT`, EINTR on a signal), and report readiness to `poll`/`select`/`epoll` (UDP sockets never showed as readable before). Datagrams to 127.x.x.x or the machine's own address stay inside the kernel. The kernel's own DNS and NTP clients bind a port implicitly when they send, so their replies are queued too. A datagram longer than the receive buffer is cut to fit. Boot-test: the port table and the socket layer over loopback (`AEROS_UDP`), plus the existing real DNS lookup and NTP exchange through the card.
- The browser's HTTP client (`net::http_get`) now runs on the TCP engine instead of its own single-shot handshake: connect with retransmission, windowed receive, orderly close, and a five-second idle timeout. The boot-test downloads a 6,000-byte body from a one-shot HTTP server on the host over the card (`AEROS_HTTP_CLIENT`) and the harness checks the request line it received. The old retransmit-backoff self-test went away with the code it covered; `tcp.rs` has the engine's own tests.
- TCP sockets for programs: `socket(AF_INET, SOCK_STREAM)` with `bind`, `listen`, `accept`/`accept4`, `connect`, `read`/`write`, `send`/`recv` (with `MSG_DONTWAIT`, `MSG_NOSIGNAL`), `shutdown`, `getsockname`/`getpeername`, `getsockopt` (`SO_ERROR`, `SO_TYPE`, `SO_ACCEPTCONN`, buffer sizes, `TCP_NODELAY`, `TCP_MAXSEG`), `poll`/`select`/`epoll`, `sendfile` to a socket and `O_NONBLOCK` (`SOCK_NONBLOCK`, `fcntl`). Eight connections at most, with an 8 KiB window each (a finished connection still waiting out `TIME_WAIT` gives up its slot when a new socket needs one). Blocking calls wait until the engine can answer and return EINTR on a signal; `connect` gives up after 30 seconds. There is no background network thread: the stack runs when a socket call, a `poll`, a sleep or any syscall happens while a socket exists, so a connection a program closed and left behind finishes its close only when something else makes a syscall. Connections to 127.x.x.x or the machine's own address stay inside the kernel. Not done: ancillary data (`SCM_RIGHTS`) and `sendmmsg`/`recvmmsg`, `SO_REUSEADDR` (accepted, no effect), out-of-band data, `SO_RCVTIMEO` and `SO_SNDTIMEO`. The boot-test covers it twice: a kernel-side loopback run (handshake, 24 KB up and 6 KB down, half-close, refused connection, `SO_ERROR` clearing), and a real run where the guest's echo server on the socket layer takes 30,000 bytes pushed from the host through the card and sends them back intact (`AEROS_TCP_NET`).
- `poll`, `ppoll` and `select` now keep rescanning while they wait instead of sleeping for the whole timeout once, so they return as soon as a descriptor is ready; a negative `poll` timeout (and `ppoll` without a timeout) waits until something is ready or a signal arrives.
- TCP engine (`tcp.rs`), a state machine independent of any card (`tcpnet.rs` connects it to the card and to an in-kernel loopback): three-way handshake both ways, `listen`/`accept` with a backlog of four, retransmission with a measured timeout and exponential backoff, slow start, congestion avoidance, fast retransmit (go back to the first unacknowledged byte, since out-of-order data is not kept), a receive window with zero-window probing, RST handling, and the full close sequence with `TIME_WAIT`. The MSS option is sent on every SYN and SYN-ACK and the peer's is honoured (536 when it sends none), so a path with a small MTU gets small segments; a simulated peer advertising 536 shows no larger segment going out. Not done: SACK, window scaling, delayed ACK, out-of-order buffering and urgent data. A boot-test (`AEROS_TCP_ENGINE`) runs it between two simulated hosts over a wire that drops segments: a clean 60 KB upload with a 20 KB download, a drop of every sixth segment, a single dropped segment that must be recovered by fast retransmit without a timeout, a receiver that reads 300 bytes per millisecond, a refused connection, a peer that never answers (exactly five SYN retries), 6,000 random hostile segments, duplicated segments and reversed delivery order. Disabling fast retransmit and slow-start growth makes the gate fail.
- Packet-filter firewall (`fw`, `fw deny <tcp|udp|any> <port>`, `fw clear`) applied at the single NIC receive path.
- The boot-test's one-connection echo server in `net.rs` still uses hand-rolled segments; everything else goes through the TCP engine.

### Storage
- FAT free-cluster search now reads each FAT sector once instead of once per cluster. This was the cause of boot-test runs intermittently taking several minutes or timing out; a full run now takes under two minutes.

- Power-loss testing of the FAT writer: a boot-test hook drops every sector write after a chosen count, and the test cuts replace, create and delete operations at every possible point over five file-size pairs, checking each result for chains that run into free clusters, shared clusters, short chains and torn or lost files. It runs on a RAM-backed FAT16 volume it formats itself, since QEMU's `vvfat` ESP aborts on such writes. FAT32 directories share the fix but are not covered by the test.
- Fixed two FAT write bugs the test exposed: replacing a file freed the old chain before the new data and directory entry were written (a power cut left a directory entry pointing at freed clusters), and a replace could leave a second entry with the same name. The new data is now written first, one directory-entry write publishes it, and only then is the old chain freed; deleting marks the entry first and frees the chain after.

- The `/home` and `/media` filesystem now shrinks a file in a power-safe order too (new size, then cut the chain, then free the tail). A power-loss test covers it: create, append, shrink, truncate-to-empty and delete are each cut at every possible sector write on a RAM disk, then the volume structure and the file's bytes are checked. A mutation check (putting the old truncate order back) makes the test report 48 structural failures and 48 torn files, so it can fail. Renaming a file over an existing one is power-safe: the destination's entry is re-pointed at the source's data in one sector write, then the source name is removed, then the old data is freed, so a cut never loses the file (it can briefly leave both names sharing it, which `fsck --repair` reports as `duplicates` and resolves). The test covers this with a rename scenario; putting the old delete-first behaviour back makes it report 13 torn files.

### Testing
- The boot-test now runs 2,500 random command lines through the real shell (`AEROS_SHELL_FUZZ`, last step before ready): read-only commands and the privileged log readers with paths, flags, numbers and junk as arguments, some piped or redirected, and the file-changing commands on paths under `/tmp` only. Commands that reboot, kill, spawn, change accounts or firewall rules, touch disks or take long are skipped; the shell runs as root because every `ear` costs a deliberate two-second re-authentication. No panic or hang turned up. The harness's readiness limit went from 240 to 420 seconds because the suite had grown to within a minute of it.
- `.github/workflows/ci.yml` checks formatting, runs clippy with `-D warnings` for the default, `boot-test` and `linux-headless` feature sets, and builds the release and boot-test kernels on every push to `main` and every pull request; a manual run can also execute `tools	est.ps1` on a Windows runner with QEMU from Chocolatey. The workflow has not been run on GitHub yet, and the boot-test harness assumes QEMU is accelerated (its 240-second readiness limit may be too short under plain emulation).
- Syscall fuzzing in two forms, both in every boot-test. A kernel-side run calls the Linux dispatcher 27,000 times with random numbers and arguments where no user memory is mapped, which exercises argument checks and descriptor lookups. A hand-assembled user process (`tools/make-fuzz-probe.py` generates it; `FUZZ_SEED` and `FUZZ_ROUNDS` change its seed and length) then makes 40,000 random syscalls from a table of the ones that are implemented, with arguments drawn from small numbers, -1, 0, random words and pointers into its own buffer, which starts with path strings for `/tmp`, `/proc` and `/sys`; it skips calls that end, signal or block the process, change its memory map and limits, or write to the console. A clean run exits 0 (`AEROS_SYSCALL_FUZZ`); a panic in the kernel halts the boot. Planting a panic behind a valid user pointer in `memfd_create` makes the boot fail, so the process does reach such code.
- `tools\test.ps1` takes `-MemoryMiB` (default 512) and accepts `-CpuCount 1`. Measured limits are in `docs/REQUIREMENTS.md`: the kernel loads from 192 MiB, the full boot-test needs about 384 MiB, and one CPU boots to the desktop.
- Capability enforcement is tested by dropping `CAP_CHOWN` and `CAP_SYS_NICE` and requiring EPERM from `chown`/`fchown` and a priority raise. Removing the `fchown` check makes the boot-test fail.
- The `AEROS_KILL` check could fail about one run in ten: a timer tick between the probe's `fork` and `kill` let the child run first. It now retries up to five times and fails only if the child wins every time.
- Boot-test no longer races the TCP echo check: the guest prints `AEROS_TCP_LISTENING` and the host waits for it before connecting.
- Deterministic mutation fuzzing of the ELF loader, compatibility inspector, antivirus scanner, image decoders and firewall frame parser runs in every boot-test (`AEROS_FUZZ`); a panic or hang fails the boot.
- New boot-test gates: process ASLR, virtio-gpu, firewall, symlink syscalls.

### ACPI events, battery and thermal
- The system control interrupt (`acpi_events.rs`, vector 54): the kernel switches the platform to ACPI mode, enables the fixed-hardware power button and every general-purpose event the firmware has a handler for (`\_GPE._Exx` edge, `\_Lxx` level), and routes the interrupt through the I/O APIC with the polarity and trigger the MADT gives. The handler only acknowledges registers and sets flags (a level event stays masked until its AML handler has run); the AML runs from `poll`, in thread context. A stuck line is shut off after 4,000 empty interrupts. The power button starts the same animated shutdown as the power menu (`AEROS_POWER_BUTTON`).
- `acpi_devices.rs` reads batteries (`_STA`, `_BIX` or `_BIF`, `_BST`: charge, rate, estimated time, cycles, model), the mains adapter (`_PSR`), the lid (`_LID`) and thermal zones (`_TMP`, `_CRT`, `_PSV`, `_HOT`) through the interpreter; new shell commands `battery` and `thermal`. The interpreter keeps a queue of `Notify` calls the handlers issue.
- Embedded controller (`ec.rs`, `PNP0C09`): the byte-wise read, write and query protocol with bounded waits, `EmbeddedControl` operation regions in the interpreter (two new hooks), `_REG(EmbeddedControl, 1)` after the handler exists, the controller's own event line and `_Qxx` dispatch. Laptop tables keep the battery, adapter and lid behind it. `_INI` of `\_SB` and of every present device now runs at load.
- Tested on the host by `tools/aml-host` against hand-assembled tables (batteries through `_BIX` and `_BIF`, absent and unknown readings, adapter, lid, thermal zones, GPE discovery and `Notify`, an EC-backed region read and written through the hooks, `_REG` and `_Qxx`) and against a model of the controller's host interface (handshakes, query order, a dead controller timing out); in the boot-test `AEROS_ACPI_EVENTS` and `AEROS_POWERBTN` check that QEMU's `system_powerdown`, sent over the monitor, arrives as an interrupt (`test.ps1` now opens a monitor port for that handshake).
- Not done, and not testable in QEMU: a real laptop's battery and EC events have not run; sleep states (S3 needs a safe resume path, so `Sleep` in the power menu still only blanks the screen); CPU frequency scaling; lid-triggered actions.

### Home volume and persistent /etc
- `datafs::adopt_home` now takes an AerFS volume labelled `AEROSHOME` as `/home` as well as a FAT one; `aerfs format|mount` does the same for an attached disk when no home is mounted. `/etc` joins `/var`, `/opt`, `/srv` and `/root` as a persistent directory bound to the home volume, seeded on a new volume with `hostname`, `hosts`, `os-release` and `aeros-release`. The boot image stays read-only by design; there is no union overlay for the rest of `/`.
- Boot-test: `AEROS_AERFS_HOME` (an AerFS volume on the RAM disk becomes `/home`, the folders and system directories appear, a file written to `/var` survives a remount, `fsck` is clean, and the FAT home comes back) and the extended `AEROS_MOUNTS` (`etc=true`: the seeded files, a write to `/etc` and its survival across a remount).

### User programs on several processors
- User tasks now run on the application processors, in parallel with each other. Kernel mode runs under one big lock (`kernel_lock.rs`, a ticket lock) that a processor takes when it enters the kernel from user mode and gives up when it returns, so the scheduler, the Linux process state and the drivers keep their one-processor assumptions while user mode runs wherever a task is dispatched. The task that holds the lock is the live one (`Scheduler::rebind` moves the process state statics, about half a microsecond); a task that waits in the kernel gives the lock up on every yield; an application processor with nothing to do dispatches a ready task from its idle loop and each runs its own 250 Hz tick that preempts the task it catches in user mode. The assembly that enters user mode releases the lock itself right after it stores the return point. Kills and signals aimed at a task running on another processor mark it and send that processor the work interrupt. The bootstrap processor keeps the desktop going (and runs tasks too only in the `linux-guest` configuration); with one processor nothing changes. `docs/SMP.md` has the design and its limits.
- Limits: kernel mode is serialised (system-call-heavy programs gain nothing from more processors), the threads of one process take turns on one processor (different processes run in parallel), no TLB shootdown, no affinity interface, blocked pipe and socket waits still poll.
- Boot-test: `AEROS_SMP_USER` (two compute-bound processes end on different processors with 99 per cent overlap, two processes make 25,000 system calls each under the lock) and `AEROS_SMP_PROGRAMS` (the init, std, threads, ptrace, pipe-and-fork and benchmark programs run on the application processors only, with the bootstrap processor halting between ticks, and end with their one-processor statuses). `lscpu` shows the scheduler and the lock counters.

### Protocol layers for hardware the emulator does not have
- `wpa.rs`: WPA2-Personal key handling: the pairwise master key from a passphrase (PBKDF2-HMAC-SHA1, 4096 rounds), the pairwise transient key, AES-128 and the RFC 3394 key unwrap, EAPOL-Key frames with their HMAC-SHA1 MIC, and the supplicant side of the four-way handshake (replay, MIC and nonce checks, group key extraction). `bthci.rs`: Bluetooth HCI commands, events (command complete and status, LE advertising reports, inquiry results), ACL headers and the reset, version, address bring-up sequence. `tpm.rs` and `tpm_device.rs`: TPM 2.0 command marshalling (`Startup`, `GetRandom`, `PCR_Read`, `PCR_Extend`) and the TIS/FIFO register protocol, probed only when the firmware lists a TPM; shell command `tpm`. `cpufreq.rs`: the firmware's processor performance states (`_PSS`, `_PPC`); shell command `cpufreq` (listing only, the kernel does not switch states).
- Tested in `tools/proto-host` against published and OpenSSL-computed vectors (IEEE 802.11i passphrase vectors, RFC 2202 and RFC 3394, FIPS-197, an independently computed PTK), a model of the TIS chip, and a model authenticator for the handshake; the boot-test checks `AEROS_PROTOCOLS`. Not done: the drivers that would carry them (a Wi-Fi chipset driver, a USB Bluetooth class driver, a TPM measured-boot hookup): QEMU here has none of those devices, so they would be written blind.

### Parallel user programs, hardening
- With tracer and tracee on different processors the debugger exposed three rules, now enforced: a task waiting in a stop saves its floating-point registers once and reloads them (with a TLB flush) when it resumes, a kill that reaches a task already waiting in the kernel is honoured by the wait loop and before the return to user mode, and `aeros-ptrace` passes with the tracer and the tracee on separate processors (four-CPU boot-test).
